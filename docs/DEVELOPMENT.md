## 公开仓库与依赖更新（2026-11-01）

根目录采用 `GPL-3.0-only`，LICENSE 与 THIRD_PARTY_NOTICES.md 同时进入源码和安装包。README 保留用户介绍，详细开发记录放本文件；发布地址统一为 `Anchorite-no/zju-all-in-one`。

Electron 固定为 44.10.1，根目录与 WeRead 可选依赖一致；electron-builder 更新到 26.18.1。MCP client 固定覆盖为 2.4.0，运行依赖锁定到已修复版本，包括 undici 8.12.3、zod 4.6.7，以及新版邮件解析/发送依赖。各 Core 仍使用自己的 lockfile，根目录 `npm ci` 的 postinstall 会安装它们。

新版 Electron 首次加载时才下载二进制。根目录 setup 在启动其他流程前串行准备 Electron，避免全新安装后多个测试进程同时解压同一目录、因 Windows DLL 占用而失败。

引擎及其子命令使用随安装包提供的 Node 24.19.0（`node-win-x64`），界面继续使用 Electron 44.10.1。引擎原生加载器锁定为 0.1.9，其 Electron 支持尚未覆盖修复证书告警的版本；直接用新版 Electron 的 Node 模式会在启动时拒绝加载。独立运行时通过明确路径启动，不依赖用户安装 Node，也不修改上游加载器或跳过其检查。运行依赖检查会拒绝缺少 node.exe 的安装包；回归覆盖没有系统 Node 的命令行、原生加载器和完整成品启动。

打包链的旧版本还会带入有告警的 minimatch/glob，因而覆盖 ASAR 4.3.1（内部 glob 14.0.3）、universal 3.0.6、EJS 7.0.2 和 minimatch 11.0.2。electron-winstaller → temp → rimraf 2 需要旧 glob 的回调接口；直接替换其 matcher 会破坏旧 glob 的私有字段依赖。`scripts/build-deps/legacy-glob` 用修复后的 glob 14 实现这一调用契约，仅用于构建，不是应用的运行组件，也不复制旧 glob 实现。

npm 的本地 override 路径相对于使用它的包解析，所以 rimraf 2 的路径写为 `file:../../scripts/build-deps/legacy-glob`；lockfile 的实际目标为仓库内 `scripts/build-deps/legacy-glob`。升级构建链时保留 `scripts/build-dependencies.test.mjs` 的检查：实际消费方解析、目录与 glob 匹配、旧回调和同步接口、限定范围的清理、ASAR 读写、EJS 编译与转义，以及 universal 动态加载。打包仍只承诺 Windows x64/NSIS，其他平台没有验收。

本次验证完成：全新 `npm ci`、四套类型检查、488 项测试及朗读器检查通过；根目录和五个 Core 的锁文件审计均为零告警。Windows NSIS 安装包构建通过，源码目录外的成品使用隔离数据、移除系统 Node/Python/npm 的 PATH，校园与公众号 CLI、引擎认证页面、配音默认关闭和桌面窗口启动均通过。GPL、第三方声明、Node.js 完整许可及主进程代码与打包内容逐一匹配；Node 二进制 SHA-256 与 nodejs.org 的 v24.19.0 官方清单一致。本次未发布新 Release，也未进行真实校园写操作或模型问答验收。

## 浙大邮箱

「插件 → 浙大邮箱」默认开启，新安装和升级都会出现；用户关闭后保留关闭状态。填完整 `@zju.edu.cn` 邮箱地址和网页版生成的 16 位客户端专用密码，连接时验证收信与发信。IMAP 使用 `imap.zju.edu.cn:993`，SMTP 使用 `smtp.zju.edu.cn:994`，均启用 TLS 和证书校验。账号不复用统一身份认证密码。

插件页只保留邮箱账号、专用密码和连接操作。「如何获取客户端专用密码」可展开查看步骤及官方网址，点击两个直达入口会在系统浏览器打开网页，生成后回到插件粘贴即可。

专用密码由 Electron `safeStorage` 加密后保存在档案目录的 `mail.json`，经父子进程 IPC 处理，不回传到页面或助手工具。没有桌面安全存储时不能保存连接；断开连接会移除凭证。草稿、附件副本和发送记录保存在档案目录的 `mail-outbox`，断开后保留，重新连接相同邮箱可查看。

查信、读正文、下载附件、写信和回复都由对话中的助手通过 `campus_mail_*` 工具完成，插件页不再提供邮件客户端界面。助手先展示完整草稿，在对话中取得对应版本的明确发送授权后调用 `campus_mail_send`，使用草稿 id 和 revision 绑定内容；修改草稿用 `campus_mail_draft` 带 id、revision，查询和清理本地记录用 `campus_mail_drafts`、`campus_mail_remove_draft`。IMAP 全程只读，不改未读标记，不加载外部图片。单封读取上限 25 MB，发送附件最多 10 个且合计 10 MB，保存草稿时固定附件内容。发送记录区分服务器接受、部分拒收和结果不确定，不自动重发。记录保存在本机，不保证同步到网页版「已发送」。第一版只支持浙大邮箱，不含 Gmail / Outlook OAuth。2026-10-18 起收件箱的新来信进「校园事务」通知栏的「个人消息」页签，打开那一页和点刷新时读，同样只读、不改未读（见「两个页签：校园通知和个人消息」）；2026-10-19 起应用开着时后台也隔 15 分钟读一次，有新来信时托盘提醒（见「托盘上的消息」）。

实现：`ui/profile/mail.mjs`、`mail-tools.mjs`、`mail-vault.mjs`，`desktop/mail-secrets.cjs`，`ui/client/MailSettings.tsx`。邮件库随根目录 dependencies 打包。验证命令：`node --test ui/profile/mail*.test.mjs desktop/mail-secrets.test.mjs`，以及 `npm run verify`。

## 初始化与 Markdown Profile

用户在应用对话中说“使用初始化 skill”即可调用自带的 `initialize` 工作流（`core/initialize/SKILL.md`）。它通过 `campus_context_initialize` 使用当前用户自己的已连接账号读取个人资料、教务课程、学在/智云/学习通入口和待办，纳入已经选择监控的聊天及邮箱连接入口。缺账号、关闭的插件、认证失败和旧缓存分别报告；不会扫描未选择的聊天或邮箱正文，也不创建提醒或执行校园写操作。

每位用户的文件在自己的应用档案目录生成，安装包只包含流程和代码。目录沿用 `%APPDATA%\CampusAgent\profile`（Windows 的 Profile/profile 同名），有 `00-个人资料.md`、`01-课程.md`、`02-平台入口.md`、`03-事项.md`，每份记录分别放在 `课程/`、`平台/`、`事项/`。MD 是正式记录，可直接编辑；原身份 JSON 首次自动转成个人 MD，`identity.json` 此后只作为旧校园命令的运行投影，由档案读取更新。原有个人记忆、备忘录和凭证保持各自用途，凭证不进入任何 MD。

课程、教学班、平台入口和群分别建档，以稳定编号关联。`campus_context_read` 检索目录，读某门课时带上已确认关联及相关监控群的近期消息；不确定关系单独列出。`campus_context_save`、`campus_context_link` 用当前 revision 更新，保存依据并保留历史版本。重复初始化不覆盖人工修改；平台事实变化作为 `latestObservation` 提示，核实合并后用 sourceRevision 确认已处理。关闭插件或更换账号后，对应来源档案不再交给模型。

关系核对由 `context-relations.mjs` 生成完整覆盖统计和分页候选，比较课程名称、学期、教师、课程号、教学班及有限消息线索，显式列出冲突与缺口。唯一且课程号、教学班、学期一致无冲突的配对可以自动确认；群聊或个人聊天必须核实。`campus_context_review` 返回清单及版本 token，`campus_context_resolve` 批量保存用户决定；被否定的配对保留“已排除”记录，不会每次初始化重新推荐。收尾重新检查每门课程的入口、群、沟通渠道和事项覆盖，区分缺课程、待核对、可用但有缺口和已关联；文件生成不等于初始化完成。具体判断流程在初始化技能的 `references/matching.md`。

初始化是跨来源建档、核对和交付的完整技能。底层 zju/邮件/聊天/公众号使用说明仍供模型查阅，但不再作为用户手动调用的技能入口；简单查询直接走工具，技能留给多步骤工作流。日程前端不在本次实现范围。

验证：`node --test ui/profile/context.test.mjs ui/profile/store.test.mjs ui/profile/identity-fill.test.mjs ui/profile/host.test.mjs`。测试使用隔离用户与模拟来源，不包含开发者的个人档案模板。

## 命令

首次开发先安装 Node.js 24.18 以上的 24.x 版本和 npm 11，然后在根目录执行 `npm ci`。根目录的 postinstall 会按各自 lockfile 安装 `core/zju`、`core/weread` 和 `core/learn/engine/vendor`；不会安装 Python 或配音模型。此前只安装过根目录依赖的工作区执行 `npm run setup` 补齐。开发和打包目前以 Windows x64 为验证目标。

`npm run verify` 统一运行四套类型检查、桌面端/Core/界面逻辑测试及朗读器测试。`npm run check:runtime` 检查运行依赖；打包前后也会检查，缺少 Core 依赖、FFmpeg 或引擎必需包时直接失败。WeRead 单独检查用 `npm run typecheck:weread`。

成品检查用 `node scripts/smoke-packaged.cjs "<项目目录以外的 win-unpacked>"`（装好的也行，给安装目录）：使用全新的数据目录和去掉系统 Node/Python/npm 的 PATH，验证引擎、认证后的网页、校园与公众号命令，并确认配音保持未安装、未启用；最后照双击那样把整个桌面程序起一次，等窗口加载出应用的页面（屏幕上会开出一个窗口，几秒后关掉；主进程报错时等满 60 秒判失败，连同报错框一起结束）。检查结束会停止测试进程，不读取实际账号。最后这一项是 2026-10-21 加的：在那之前只起引擎，主进程在成品里一启动就报错也查不出来（见下面 0.1.7 的记录）。

```bash
npm start
```

一条命令打开应用，也可以直接双击 `start.cmd`。它会构建界面包、启动窗口，并在窗口开着时监听 `ui/client/`：改完代码约一秒生效，不用重启。改 `desktop/`、`app.patch.yml` 或引擎侧的 `ui/profile/*.mjs` 需要关掉重开；没重开时界面是新的、后台是旧的，这时页面上的请求一出错就会改成提示「请完全退出应用再打开」。做法是界面包每次构建时记下引擎侧代码的指纹，引擎启动时也算一份，页面拿两份比（`ui/profile/stamp.mjs`、`ui/client/api.ts`）。同一份数据目录只会开一个：已经开着时再开一次，是把原来的窗口叫到前面，新开的那个自己退出。

```bash
npm run typecheck
```

```bash
npm run typecheck:core
```

打出发布用的安装程序 `dist/CampusAgent-Setup-<版本>.exe`（未签名，约 310 MB）。它是一个向导：欢迎页、选安装位置、确认位置并选要不要桌面快捷方式、安装、完成页上勾不勾「运行 CampusAgent」（见下面「安装向导」）。默认装在 `C:\Program Files\CampusAgent`，装给这台电脑上的所有用户，要管理员权限（双击时系统弹一次授权）。0.1.5 及以前双击就装、不问位置，装在 `%LOCALAPPDATA%\Programs\campus-agent`、只给当前用户；从那些版本升上来时旧的那一份会被卸掉，换到新位置。卸载不删 `%APPDATA%\CampusAgent` 里的数据。装新版本会先把旧版本的安装目录整个换掉，所以应用自己不往安装目录里写东西。

**安装程序为什么改成了 zip。** 0.1.2 及以前的安装程序装得很慢（用户 2026-10-11 说的）。原因是文件多加上 electron-builder 的装法：成品有 19,494 个文件（1.4 万个不到 4 KB，绝大多数在 `node_modules` 里），而它默认的装法是先把压缩包整个解到临时目录，再用系统的复制把每个文件拷进安装目录，最后删掉临时的那一份（`app-builder-lib/templates/nsis/include/extractAppPackage.nsh` 的 `extractUsing7za`）；升级时旧版本的卸载程序还要先把旧文件一个一个挪走。拿 0.1.2 的安装包在开发机上（NVMe，没开杀毒）把这几步拆开量过：解到临时目录 19 秒，复制进安装目录 93 秒，删临时目录 3 秒。开着杀毒的普通笔记本上每一步都要再慢几倍。改了三处：

- `package.json` 的 `build.nsis` 加了 `useZip` 和 `differentialPackage: false`：应用打成 zip，安装时直接解进安装目录，每个文件只写一次。代价是安装程序从 244 MB 变成 316 MB（zip 压得不如 7z），以及没有 `.blockmap`、更新时不能只下变了的部分（本来也是整个下的，`desktop/update.cjs` 里把这种下法关掉了）。
- `scripts/after-pack.cjs` 多了一步 `dropDeadWeight`：删掉各个 `node_modules` 里的源码映射（`.map`）和类型声明（`.d.ts` 等），运行时没有东西读它们。5,680 个文件、48 MB，成品剩 13,816 个文件。说明文档没删（引擎有的页面会读包里的说明）；我们自己的代码和 `core` 里的不动。
- 解 zip 的组件（nsisunz）写不了名字带中文的文件：装到 `core/learn/朗读器.cmd` 就弹「Failed to decompress files」停住，后面的都没装上（第一次试装就是这样）。这个文件是配音朗读器的启动脚本，应用里用不上，在 `build.files` 里排除了；`after-pack.cjs` 另加了一道检查（`oddNames`），成品里再出现名字带非 ASCII 字符的文件，打包直接失败并指出是哪个。**以后往 `core/` 里放文件，名字用英文。**

**安装向导。** 0.1.5 及以前的安装程序双击就直接装，不能选位置，不问要不要快捷方式、装完要不要打开，装在哪也不说（用户 2026-10-12 说的）。那是 electron-builder 默认的「一键安装」。改成了向导式的：`package.json` 的 `build.nsis` 加了 `oneClick: false`、`perMachine`、`allowToChangeInstallationDirectory`，再用 `include` 带上我们自己写的一段 `scripts/installer.nsh`（模板在几个位置留了宏给项目插东西，为什么这样写都在那个文件的注释里）。走下来是五页：

1. 欢迎页。
2. 选安装位置。可以直接选盘符（`D:\`）。
3. 「选择附加任务」（我们加的）：写明最后装到哪个文件夹，一个「创建桌面快捷方式」的勾，默认勾着。开始菜单里的快捷方式总是建。
4. 安装。
5. 完成页，「运行 CampusAgent」默认勾着。

几处是我们自己定的：

- **装到 `C:\Program Files`，要管理员权限**（`perMachine`），和常见的软件一样。第一版向导是只装给当前用户、不要管理员权限的（为的是应用自己更新时不弹授权），用户看了以后定的：就该装在 Program Files，静默更新本来就不需要（2026-10-12）。带来的变化：双击安装程序、卸载、应用自己装新版本时，系统都会弹一次授权，安装包没有签名，弹出来的是「未知发布者」；快捷方式建在所有用户的桌面和开始菜单里；应用运行时没有权限往安装目录里写东西（本来也不该写，见「数据放在哪」）。模板里「仅为我安装 / 为所有用户安装」那一页不出来。
- **最后装到哪个文件夹**（`campusSettleDir`）。卸载和升级都会把安装文件夹整个删掉，所以应用要有一个只属于它的文件夹：选的文件夹里已经装着本应用（程序和卸载程序都在）就原地装；里面有别的东西，或者路径里不带应用名，就装进它下面的 `CampusAgent` 子文件夹（选 `D:\` 得到 `D:\CampusAgent`，选 `D:\Software` 得到 `D:\Software\CampusAgent`）。第 3 页上显示的是这样定下来以后的位置。
- **开始装之前查两件事**，不过就弹窗说明、留在第 3 页，等用户回去换位置。不查的话要等解压失败才知道，那时旧版本已经卸掉了。一是路径长度：解压的组件写不了超过 Windows 老限制的路径（文件 259 个字符，文件夹 247 个），位置选得太深，装到一半弹「Failed to decompress files」（拿一个 248 个字符的位置试出来的）。上限在打包时由 `after-pack.cjs` 按成品里最深的文件算出来（`installDirRoom`，0.1.5 的内容是 82 个字符，最深的是 `dsh-otel` 里一个 176 个字符的文件），经环境变量 `CAMPUS_INSTALL_DIR_MAX` 交给安装脚本；算出来连默认位置都装不下时打包直接失败。二是写不写得进去（只读的盘、连管理员也没有权限的文件夹）：往上找到第一个已经有的文件夹，在里面建一个空文件试一下。
- **安装程序只带简体中文和英文**（`installerLanguages`）：系统是中文的显示中文，别的显示英文。我们加的那几句话两种语言各写了一份，`installer.nsh` 里的语言要和这一项一一对应，哪边多出一种打包都会失败。

应用自己更新走的还是静默安装（`--updated /S`），不出向导的任何一页，装在原来的位置，桌面快捷方式有没有都照原样；只是安装程序要管理员权限，系统会弹一次授权。应用里的更新器（electron-updater）先照常直接起安装程序，被系统拒绝（`EACCES`）以后改用安装目录里的 `resources\elevate.exe` 提权再起一次，这是它自带的退路，已经发出去的 0.1.3 到 0.1.5 也是这样升上来。（`latest.yml` 里可以标明「要管理员权限」让更新器直接走提权，但 electron-builder 只在带 `.blockmap` 时才写这个标记，我们没有。）选了「稍后」的，退出应用时装新版本，那时也会弹授权。从 0.1.5 及以前升上来时，新的安装程序会先把装给当前用户的那一份卸掉（文件夹、注册表项、那个用户自己桌面和开始菜单里的快捷方式），再装进 `C:\Program Files\CampusAgent`；`%APPDATA%\CampusAgent` 里的数据不动。

## 数据放在哪

应用自己的会话和设置在 `%APPDATA%\CampusAgent\`，和本机装的 DeepSeek Harness 的 `~\.dsh` 分开。

API Key 统一放在一个文件 **`api-keys.local.yaml`** 里。开发时它在项目根目录（`D:\Innovation\api-keys.local.yaml`），直接修改 `refs` 下的 `DEEPSEEK_API_KEY` 即可；装好的应用里它在数据目录（`%APPDATA%\CampusAgent\api-keys.local.yaml`），升级不会丢。对话和网页搜索共用它。应用设置里的 Key 输入框也写回这一份文件，保存后对后续请求生效，直接编辑文件同样会自动加载。放哪由壳决定（`desktop/main.cjs` 的 `keysDir`），经 `CAMPUS_KEYS_DIR` 告诉引擎，微信公众号插件认验证码用的也是这一份里的 Key。

`DEEPSEEK_API_KEY` 在这里仅是文件字段名。启动不再读取同名环境变量、不加载 `.env`，也不从 `~\.dsh` 或旧的应用凭据文件自动复制密钥。首次配置可以照 `api-keys.example.yaml` 填写，或直接在界面输入保存；文件不存在时不会沿用旧 Key。

本地密钥文件已加入 `.gitignore`，打包只包含示例。0.1.0 的便携包把它写在解压目录的 `resources/app/` 里，从那一版换过来要重新填一次 Key。

引擎默认把完整会话日志随请求额外上传给 DeepSeek，`app.patch.yml` 里关掉了。

## 用 ChatGPT 账号登录

设置 → 模型页最下面有一块「ChatGPT」。登录后模型选择器里多出 GPT，和 DeepSeek 并列，随时切换；新对话默认用 GPT-6.1 Sol、推理强度 Xhigh（已经开着的对话各用各的，不变）。退出登录后 GPT 从选择器里消失，默认模型改回引擎原来的 DeepSeek；登录期间自己把默认模型换成了别的，退出时不动它。两种登录方式：

- 「登录」：在系统浏览器里打开 OpenAI 的登录页，登完浏览器跳回本机（`localhost:1455`），应用自己变成已登录。浏览器没能跳回来时，把它地址栏里的地址贴进卡片里的输入框。
- 「用代码登录」：卡片上显示一段代码，在 OpenAI 的验证页里输入。浏览器和应用不在同一台机器、或者 1455 端口被占时用这个。

登录、令牌的保存和刷新、发请求都是引擎自带的（`@deepseek-ai/dsh-llm-pi-ai` 的 `openai-codex` 线路，底下是 pi-ai）：用的是 OpenAI 的 OAuth，和 Codex 客户端同一套；请求走 Responses 协议，发到 `chatgpt.com/backend-api`，算在 ChatGPT 订阅里（pi-ai 标的是 Plus / Pro），不需要 API Key。引擎的模型页只给这条线路留了填 API Key 的输入框，没有登录入口，我们补的是：

- `ui/profile/chatgpt.mjs`：替页面发起、取消登录，把要人去的页面、要输入的代码、要贴回来的地址转给页面；登录成功后把线路写进模型设置（引擎的 `llm-pi-ai` 配置里的 `providers.openai-codex`），再把新对话的默认模型写进 `agent-default-model`；退出时把默认模型改回去、撤掉线路、删掉令牌。
- `ui/client/ChatGptCard.tsx`：那一块卡片，登记在引擎留的 `settings.models.footer` 上。
- `desktop/main.cjs`：`auth.openai.com` 的页面交给系统浏览器开，不进应用自己的阅读窗口。

令牌和 DeepSeek 的 Key 存在同一个文件里（`api-keys.local.yaml` 的 `records` 下面的 `llm-pi-ai/openai-codex`），这个文件不要发给别人。退出登录只在本机删掉令牌，不通知 OpenAI。

有哪些模型、各有哪几档推理强度，取自 pi-ai 自带的模型表（现在是 0.87.1 的八个：GPT-5.3 Codex Spark、GPT-5.5、GPT-5.6 Luna / Sol / Terra、GPT-6 Astra / Luna / Sol），不是向账号查的：表里有而账号用不了的模型，要到发消息时才报错。GPT-6.1 Sol 比这张表新，是照 pi-ai 1.1.0 的模型表抄进 `chatgpt.mjs` 的 `NEWER_MODELS` 补上的（名字、上下文长度、输出上限、能看图、推理档位）；引擎自带的 pi-ai 不认识它，所以它没有自带模型那几项按模型开的协议开关，只走这条线路通用的发法。默认模型选的就是它，改默认模型改 `chatgpt.mjs` 的 `DEFAULT`。表里有的档位只是别的档位的别名（`minimal` 发出去就是 `low`），写线路时去掉了，所以选择器里每一档发出去的值都不一样：GPT-5.5 是 Off、Low、Medium、High、Xhigh，GPT-6.1 Sol 是 Low、Medium、High、Xhigh、Max。引擎升级带来新的模型表后，重新登录一次线路才会按新表重写。

验证过的：在真实引擎上发起浏览器登录（拿到 OpenAI 的授权地址，带 PKCE）和代码登录（OpenAI 发回了代码）、取消、登录成功后那一步对模型设置和默认模型的写入、退出时的撤销和默认模型改回、选择器里 GPT-5.5 和 GPT-6.1 Sol 的档位、新对话默认显示 GPT-6.1 Sol / Xhigh、登录页由系统浏览器打开。**没有验证的：真的登完一个账号，以及登录后发一条消息**（GPT-6.1 Sol 是补进去的，尤其要试），这两步要有 ChatGPT 账号的人在应用里做一遍。引擎进程自己访问 `auth.openai.com` 和 `chatgpt.com`，本机要连得上。

## 对话和它的文件夹

新会话默认不用选工作区，做法照 Codex：聊天记录在应用数据目录（`%APPDATA%\CampusAgent\home`），每个对话另有一个自己的文件夹 `文档\CampusAgent\<日期>\<时分>`，对话里产生的文件落在里面。文件夹由 `ui/profile/chats.mjs` 建；环境变量 `CAMPUS_CHATS_DIR` 可以把整个位置换掉，界面测试时一定要设，免得往真实的「文档」里写。删除对话只删聊天记录，不动文件夹。对话页右上角的文件夹按钮（引擎自带）能打开它。

引擎要求每个会话属于某个工作区，新对话页没有工作区时连输入框都不可用，也没有给这件事留扩展点。`ui/client/chats.ts` 的做法是：读工作区列表时在前面加一个虚构的工作区「对话」，成员是所有不属于用户自己添加的工作区的会话；再包住引擎 `uiWorkspace` 服务的三个方法，让「新会话」和启动时默认落在「对话」里。引擎服务端不知道这个工作区，所以侧栏上它那一行的工作区菜单用样式收起来了。从真实工作区那一行的加号新建，仍是引擎原来的行为。引擎第一次启动会自己建一个「默认工作区」（`文档\deepseek-harness\default-workspace`），我们不用它：启动时发现它登记着就取消登记，目录、文件和会话都不删，会话改显示在「对话」里。启动时还会把用户自己添加的工作区都展开，否则它们不是当前分组，引擎会把它们折叠起来，看着像会话没了。**引擎升级后这一块要对着 `dsh-client-ui-workspace` 重新核一遍。**

新对话页的 Agent 模式切换、设置里的「Agent 预设」和「内置插件」在 `app.patch.yml` 里关掉了（`ui-agent-preset`、`ui-settings-plugins`、`ui-settings-plugin-inventory`），只收起界面，引擎里的预设和插件照常工作。

## 对话的权限

输入框下面的权限有三档：仅可查看、工作区内修改（新会话默认）、完全权限。前两档靠一道文件沙箱：助手运行的命令和写文件的工具只能改会话自己的文件夹，Windows 上命令是在一个降了权的进程里跑的。它是给在代码仓库里干活的编程助手设计的，照原样用在我们的对话里有两处对不上：

- 对话的文件夹是 `文档\CampusAgent\<日期>\<时分>`，校园命令却要把登录状态和缓存存到应用数据里的 `zju` 目录，下载的课件、转写、讲解落在 `文档\CampusAgent` 下面各自的文件夹，都在这个文件夹外面。2026-10-12 的一次真实对话（默认的「工作区内修改」，让它查 CC98）：`zju.ts` 写登录状态时报 EPERM，模型没看出是沙箱挡的，转头去读引擎那份修文件夹权限的技能，只好打断。在这之前应用里没有真的跑过校园命令，所以一直没发现：默认的档位下，第一条校园命令就是坏的。
- 降了权的进程起不了带管道的子进程，也连不上命名管道（引擎文档里写明的边界）。校园命令里的 ffmpeg、转写、读文档，还有公众号（连壳开的管道），在里面都做不了。

2026-10-12 改成对话有自己的范围，代码在 `ui/profile/permissions.mjs`：

- **对话里能写的是整个 `文档\CampusAgent`**，不只是这一次对话的文件夹：各次对话的文件夹、课程、讲解、转写都在里面，别处照旧要先问。相对路径还是从对话自己的文件夹算，放宽的只是围栏。认的是会话的文件夹在不在对话总目录下面（`CAMPUS_CHATS_DIR` 换掉总目录时跟着换）；用户自己添加的工作区不变。助手在一个对话里第一次运行自己写的命令时，引擎要给整个 `文档\CampusAgent` 登记一遍写入凭据（把里面的文件走一遍），只有这一次慢一点。
- **应用自带的校园命令不进沙箱**，三档都一样：整条命令就是 `node <core>\zju\scripts\zju.ts …` 或 `node <core>\weread\scripts\weread.ts …`（名单是 `TRUSTED_SCRIPTS`）。认的是整条命令的样子（`trustedCommand`）：`node` 后面直接跟名单里的脚本，其余每个词都是字面量；有管道、分号、重定向、变量、子表达式、换行的都不算，`node` 和脚本之间带选项的也不算（`-e`、`--require` 能带进别的代码），结尾的 `2>&1` 可以有。拿不准就不算，照旧在沙箱里跑。learn 的引擎脚本（`build.mjs`、`lint.mjs`、`shots.mjs`）不在名单里：它们会执行讲解里的脚本，那是助手自己写的代码。前两档下它们起不了 esbuild 和浏览器，助手照引擎的办法为这一条命令申请完全权限，弹出来问一次。
- **告诉模型的话跟着改**：引擎每一轮告诉模型「只能改这次对话的文件夹」，我们在它后面补两句，一句是对话里实际能写的范围，一句是校园命令单独一条执行、后面不要接管道和重定向。只在前两档出现。

引擎没有给这两件事留扩展点：策略里一个会话只有一个可写的根，而且写文件的工具拿这个根当相对路径的起点，所以不能直接改策略。做法是包住两个服务的方法，`ctx.shell.resolve`（每条 pwsh 命令执行前定策略的地方）和 `ctx.fs.checkedTarget`（写文件、改文件的工具过围栏的地方），写法和界面那边的 `chats.ts` 一样，挂在服务对象自己身上，撤掉就露出原来的。**引擎升级后对着 `dsh-pwsh-sandbox`、`dsh-fs-sandbox` 重新核一遍**；方法不在了会在日志里提示，范围退回引擎原样。

试过没有做成的一条：让沙箱里的命令也能写校园命令的数据目录，这样接了管道的校园命令也能用。把工作区的写入凭据登记到那个目录上是登记得上的（用引擎的 `AclWriteGrant` 实测过，沙箱里的进程写得进），但这台机器上的 PowerShell 是商店版，它在沙箱里连 `AppData` 都看不到：目录明明在，`Get-Content` 说路径不存在。所以**接了管道、分号、重定向的校园命令在前两档下仍然会失败**（读不到登录状态），靠上面那句话让模型不这么写；输出太长时引擎自己会存成文件。

验证：`ui/profile/permissions.test.mjs`（哪些命令算、哪些不算，包括弯引号这类 PowerShell 也当引号的写法；对话里放宽、工作区里不动；包上去、撤下来）。在隔离的数据目录里把引擎真的起来试过：两个方法都包上了；默认档位下 `zju.ts` 是不受限跑的，接了管道的仍在沙箱里；对话文件夹和 `讲解\` 写得进，对话总目录外面写不进；写文件工具的围栏同样。又在隔离实例里用真实模型发了一句「查一下学工部最近的通知」：默认的「工作区内修改」，模型收到了补的那两句，`zju.ts notice list`、`notice sources` 都跑完了，没有 EPERM。同一天又在真实的数据目录里（填着账号）走了一遍：默认档位下重发那句「帮我查找CC九八上的情感内容」，六条 CC98 命令都拿到了结果，46 秒答完，上次写不进去的 `zju\sessions\cc98-anchorite.json` 写进去了；再让它用 PowerShell 各建一个文件，对话文件夹里的建成了，`D:\` 根目录的被拦住（`[sandbox: file access denied under workspace-write mode]`），模型照补的那句话说对了能写的范围，没有去申请更高权限。**没验证的**：learn 在前两档下申请权限的那一问；别的系统（现在只在 Windows 上发布）。

## 助手的底层说明

引擎的系统提示原本是给编程助手写的。2026-10-07 的一份真实对话日志里，模型收到的开头是「You are an AI agent powered by DeepSeek Harness.」「You are a coding agent powered by the deepseek-flash model.」，后面还有两段：引擎的源码在哪（指到的是我们的项目目录，装好的应用里是安装目录）、它的网页界面怎么开发。问它是谁，答的是「DeepSeek Harness 中的编码智能体」。`app.patch.yml` 里写过的那句中文人设没有到模型那里：引擎的每个 Agent 预设（`dsh-web-app/presets/standard.patch.yml` 等）自己带一条人设，会把 `system-prompt` 那一行写的盖掉。

2026-10-11 换成我们自己的，两处：

- **`core/AGENT.md`** 是底层说明的正文，每次对话都在：助手在哪、对面是谁（学生本人，多数不是学计算机的）、应用里有哪几页、怎么回答、手里有哪些技能、东西放哪（学习页是照文件夹画的，放错了等于没做）、记忆、备忘录、技能各在什么时候写、什么事要先问（会改动学校系统、会发出去、会花钱的）、运行环境。具体一件事怎么做不写在这里，写在各个技能里。改它不用重新打开应用，下一轮对话就生效。
- **`ui/profile/agent.mjs`** 把它放进系统提示（一段，名叫 `campus-agent`，排在人设后面、引擎讲各个工具怎么用的那些段前面，里面的花括号不做替换），并在每次拼系统提示的最后一步（引擎的 `system-prompt/assemble`）做两件事：把预设带的那条「coding agent」人设换成我们的一句（`PERSONA_TEXT`，模型的名字只有这一句能带上）；去掉引擎写给改引擎的人看的三段（`harness:identity`、`harness:source`、`app:web-surface`）。引擎讲工具怎么用的那些段、工作目录那一句、交付文件怎么引用那一段都留着。

原来放在 `host.mjs` 里的 `campus-profile-policy` 一段（三样资料各记各的）并进了 `AGENT.md` 的「留下来的资料」一节，文字没改。`app.patch.yml` 里那句不起作用的人设删了。

验证：`ui/profile/host.test.mjs` 核对这一段在、三段被去掉、人设被换掉、别的段不动。在隔离实例里真开了一个对话，从它的会话日志里读出模型实际收到的系统提示：开头是我们的人设和 `AGENT.md`，「DeepSeek Harness」「coding agent」和那两段都不在了，工作目录那一句还在。要再看一次，解 `%APPDATA%\CampusAgent\home\sessions\<对话>\session.v4.jsonl.zstd`（一帧一帧接起来的 zstd）里 `system/message` 那一条。**没验证的：换了以后模型答得怎么样**，那一次对话是在没有 API Key 的隔离实例里发的，只走到发请求之前。

引擎自己还会读一份用户级的 `AGENTS.md`（`%APPDATA%\CampusAgent\home\AGENTS.md`，没有这个文件就什么都不加），以用户消息的身份放在对话最前面。没有用它装底层说明：它在数据目录里，升级带不过去，而且引擎明说它压不过系统提示。以后要给用户一个「自己写几句长期的要求」的地方，可以接它。

我们自己的页面（插件、校园事务和学习页）共用 `style.css` 里 `.campus-page` 这套骨架（设置里的个人档案画在引擎设置面板的内容栏里，没有这套骨架，外面一层是 `.campus-settings`），尺寸照引擎自带的插件页：内容居中、960px 封顶、标题 20px。底色、文字、圆角、描边用引擎的 `--dsw-*` 变量，深浅色主题自动跟随；按钮、开关、标签用 `@deepseek-ai/dsh-client-ui-primitives` 里现成的。内容直接落在页面底色上，不垫底板。整页是平的：不用阴影把东西浮起来（用户 2026-10-11 的原话：浮起效果最糟，会让页面从 2D 的软件变成 3D 的，不伦不类），要垫底色时用很淡的灰（同一天：先嫌引擎放标签的那种灰做成的标题条「灰灰的色块难看」，后来定的是比它再淡一档，见「学在浙大那一边」）；悬停和点中时那一层浅底是引擎自己的，照旧。颜色只动一处：整个应用里打开的开关是蓝色（引擎的品牌蓝，规则在 `style.css` 最前面「开关」一段，对引擎自己的页面也生效），按钮和别的控件都是引擎原本的黑白。2026-10-11 在学习页的章节标题条上试过很浅的蓝，用户看了说丑，撤了，别处也不要再试。详情页和表单照引擎官方插件的设置页（`dsh-client-ui-plugin-manager` 的详情页、primitives 里的 `SettingsForm` 和字段）：图标在左、开关在右，下面是名字和一句话；表单的标签在上、输入框通栏，并排的几项放进网格，一组一个小标题，保存按钮在左下角。这些尺寸是对着原版页面量过的，引擎升级后如果原版变了，按 `style.css` 里「详情页」「表单」两段的注释重新对一遍。插件图标照引擎原版：48px 的细线框，里面是 36px 的图形。通用工具直接用 DeepSeek 自己的图标（网页搜索是引擎的图形，其余三个是各插件包自带的 `icon.svg`）；校园功能的六个在 `ui/client/artwork.tsx` 里照同一种画法画，用引擎图标的那几组渐变。共用的小控件在 `ui/client/controls.tsx`。

页面上只放名字、控件和必要的状态，不写解释性的小字。

## 返回

我们自己的页面里，点进去的那一层（作业详情、备忘的单条和编辑、插件详情、技能详情、设置里的记忆）顶上都有一行返回，是 `ui/client/controls.tsx` 的 `Crumb`。它在场时，下面几种输入也算点了它（`ui/client/back.ts`）：

- 鼠标侧键的后退。有两条路进来：页面自己收到的鼠标事件（`button` 是 3）；壳把系统的「浏览器后退」命令转过来（`desktop/main.cjs` 听 `app-command`，经 `preload.cjs` 变成窗口上的 `campus:back` 事件）。同一下按键两条路可能都到，300 毫秒内的第二次不算。
- 键盘上的 Alt+← 和后退键。

引擎不用浏览器的历史记录，壳原来也不处理后退，所以是直接认这几种输入，没有往历史记录里写东西。几个返回同时在场时认最后出现的那个（设置面板盖在页面上时是面板里的）；上面盖着确认框（删除、放弃修改）时不动；编辑到一半按后退，和点返回一样先问要不要放弃修改。新做的页面只要顶上用 `Crumb`，不用再写别的。

验证过的是模拟出来的这几种输入（隔离实例里派发鼠标事件、`campus:back` 和键盘事件）；真实鼠标的侧键没法在离屏窗口里按，要在应用里实际按一下确认。

## 关闭窗口和托盘

设置 → 通用设置里有一个开关「关闭窗口时隐藏到系统托盘」，默认开（2026-10-21 起，见下面「系统通知和托盘默认开」；原来默认关，点关闭按钮就是退出应用）。打开后点关闭按钮只把主窗口藏起来，引擎照常运行，托盘上多一个图标：点它把窗口叫回来，右键菜单里有「打开主窗口」和「退出」。窗口藏着时再打开一次应用，也是把它叫回来。Windows 11 默认把新图标收在任务栏的「显示隐藏的图标」里。

验证过的：在隔离实例里给主窗口发关闭消息（和点关闭按钮是同一条路）、点真实的托盘图标、再启动一次、关掉开关后再关窗口。页面里的 `window.close()` 不走这条路，会直接关掉窗口。托盘右键菜单里的两项只在 `desktop/tray.test.mjs` 里用假的托盘测过，没有真的点。

## 检查更新

装好的应用会自己查新版本：启动后十五秒查一次，之后每六小时一次；设置 → 通用设置里的「检查更新」一行可以手动查，也看得到走到哪了。有新版本就自己下载（一整个安装程序，约 310 MB），下完弹窗问「立即安装并重启」还是「稍后」：选前者应用关掉、不出界面地装好、自己重新打开（安装程序要管理员权限，系统会先弹一次授权，见「命令」里的「安装向导」）；选稍后，那一行留着「安装并重启」，下次退出应用时也会装上（那时也弹授权）。开发时（`npm start`）不查。

新版本取自 GitHub 上这个项目的 Release（`electron-updater`，更新源是 `package.json` 里 `build.publish` 那一项，打包时写进成品的 `resources/app-update.yml`）。仓库是公开的，`build.publish` 里 `private` 是 `false`，不用 GitHub 令牌也能查、能下：这时 `electron-updater` 读 github.com 上公开的发布页（`releases.atom`、`releases/latest`）和下载地址，不走 `api.github.com`。令牌是可选的，有就带上，按这个顺序找：环境变量 `GH_TOKEN` / `GITHUB_TOKEN`；设置里填的（读不到更新时那一行会出现一个输入框，用系统的加密存在 `%APPDATA%\CampusAgent\update-token`）；本机 GitHub CLI 的登录（`gh auth token`）。带了令牌，`electron-updater` 改走 `api.github.com`，按这个身份算次数；令牌被拒了（过期、填错），不带令牌再查一次。带不带都读不到（GitHub 回 401、403 或 404），那一行会写明读不到，多半是仓库又改回了私有，这时要一个能读它的令牌。

没有令牌也去查，这只对 0.1.7 以后打出的新版本生效。已经装着的 0.1.3 到 0.1.7 照旧：成品里的 `app-update.yml` 写着 `private: true`，代码里找不到令牌就停在「读不到」，根本不去查。仓库公开以后，给这些旧版本一个令牌照样能查到新版本、下载、装上（能读公开仓库的令牌就够，不用额外勾权限），装上新版本以后就不再需要令牌；没有令牌的，要手动装一次新版本。

**发版时 Release 里要放两个文件**，都在 `dist` 里：`CampusAgent-Setup-<版本>.exe` 和 `latest.yml`（0.1.2 及以前还有一个 `.exe.blockmap`，安装程序改成 zip 以后没有了，见「命令」）。应用靠 `latest.yml` 知道最新版本是哪个、安装程序叫什么、校验值是多少；少了它，装着旧版本的应用会报找不到更新。Release 不能是草稿或预发布，标签是 `v<版本>`。带这项功能的第一个版本是 0.1.3，更早的版本要手动装一次。

代码：`desktop/update.cjs`（状态、定时、找令牌），在 `desktop/main.cjs` 里接上 `electron-updater`、弹窗和存令牌；页面经 `preload.cjs` 的 `campusShell` 读状态、点按钮（`ui/client/UpdateRow.tsx`）。

验证过的：装一个版本号改成 0.1.1 的测试包，让它对着真实的仓库（当时还是私有的）查到 0.1.2、用本机 GitHub CLI 的身份下载完、弹窗、点立即安装后装好并自己重新打开成 0.1.2。没验证的：仓库公开以后不带令牌查和下载（只有单元测试，还没有装好的新版本对着真实仓库试过）、令牌被拒后不带令牌重查（只有单元测试）、在设置里填令牌这条路（只有单元测试）、定时自动查（只测了手动点检查和定时器的设置）、选「稍后」之后退出时安装。自己重新打开的那一次不带启动参数，用的是默认的数据目录。

## 看网页的窗口

页面里点开的链接（通知原文、公众号文章、对话里的网址）都在应用自己的一个窗口里开，不去系统浏览器（`desktop/reader.cjs`，在 `main.cjs` 里接到主窗口的「开新窗口」上）。原因是用户提的：系统浏览器里要重新登录统一身份认证和 WebVPN，还可能把应用存着的会话顶掉。引擎自带的右边栏浏览器在我们这种组合下是关着的（它只在配置名叫 `desktop` 时打开），没有用它。

这个窗口复用 ZJU Core 已经登录好的会话，走法和 Core 自己访问校内网站时一样：

- 打开前把 Core 存下的统一身份认证和 WebVPN 的 cookie（`%APPDATA%\CampusAgent\zju\sessions\` 下的 `zjuam.json`、`webvpn.json`）放进窗口自己的会话里。只放这两样、只放 `zju.edu.cn` 下面的；各个网站自己的登录状态由它们经统一身份认证各自建立。窗口的会话不落盘，关了应用就没了。
- 校内网站怎么走看插件页「校园账号」里选的访问方式：默认经 WebVPN，选了校园网直连就直连。经 WebVPN 时统一身份认证仍然直连（登录状态在本机，不在 WebVPN 那边）：页面被带去 WebVPN 形式的统一身份认证地址时改成直连的；它带着票据跳回校内网站时，再把地址改写成 WebVPN 形式。地址改写的写法和 Core 一样，只是不带结尾的 `vpn-12-o2` 标记（那个标记让 WebVPN 原样返回内容，这里要的是它改写好链接的页面）。
- 标注为公网可达的网站不绕 WebVPN，直连：Core 里实测过的几个（教务网、学在浙大、智云、三全育人），加上通知模块的逐站标注表（见下）。没标注的校内网站一律经 WebVPN，它公网的、校内的都到得了。
- 存着的会话过期了（落到了统一身份认证或 WebVPN 的登录页），让 Core 自己重新登录一次（`zju zjuam session login` / `zju webvpn session login`），再放一遍 cookie 重开，不让用户在这个窗口里输密码；每个系统只试一次，登录不上就在窗口里说明原因。WebVPN 的会话存了超过五个半小时（Core 按六小时算过期）时，打开前先续上。

## 执行过程（右边栏）

右边栏的「执行过程」页签把这次对话里的工具调用画成一张线路图，给不看命令的人看：助手查了哪些网站、每一步拿到了什么。一根细线从「你的问题」画到「回答」，这根主线是助手自己；每去一个网站，从主线弯出一条支线，圆圈在支线上，线的左边是网站名，右边是在那里做了什么，行尾是拿到几条。三种关系三种画法：换了一个网站，另起一条支线；接着在同一个网站上做别的，竖着接在圆圈下面（网站名不重复写）；同一步里去的几个地方，共用一条从主线弯出来的竖线，各自横着挂在这条竖线上，谁也不挂在谁下面。线都往下走，除了分出去的地方和拐进圆圈的那一下是弯的，其余都是直的。只用黑白灰，失败的才是红的（行尾写「失败」）；没有表头、标签和色块。圆点分三种：问题和回答是实心的，在主线上；查了一个网站是空心圈，在支线上；读写文件这类本地操作是小灰点，在主线上（失败了是和圆圈一样大的红点）。点一行，详情（用时、拿到的前几条、失败的原因、原始命令）接在它下面。更早的几轮各折成一行。一次调用一行，不合并：同一种动作做了几次就是几行，本地操作也一步一行、不收起（2026-10-11 用户要的：步骤多才看得出它做了多少事）。顶上一句写去了哪几个网站、一共多少步；每一行名字后面写这一次针对什么（哪位老师、搜的什么词；命令里只有编号时，用结果里那一条的标题），纯数字的编号不写。

现在的样子见 `plans/shots/执行过程页-一步一行.png`（一轮选课，15 步：教务网读课表、搜课、查教学班，查老师和 CC98 同时发出，再同时查三位老师、开三个帖子。这张是把 `TraceTab.tsx` 用编好的数据画在隔离实例的页面里截的，样式是真的，数据是假的）。`plans/shots/执行过程页-支线画法.png` 是合并还没去掉时的同一种画法（同一种动作的几次合成一行，写「3 次」）。`plans/shots/执行过程页-选课.png` 是同一轮在应用里的截图，画法是上一版的：所有站都串在主线上，只有同一步里的才分出去并排。2026-10-09 改掉它，是因为一根线把站穿起来读着像「后一个接着前一个」，换了网站也看不出来；而引擎没记谁依赖谁，所以现在只画「同一个网站接着做」「换了网站」「同时发出」这三样，不画依赖。

2026-10-08 试过照 Git Graph 做的一版（彩色的线、带表头的表格、左边带一条色块的网站标签），用户看了觉得俗气，换成了现在这样；以后不要往回改。

**用的时候自己打开**（2026-10-12）。发出问题、助手开始做事时，右边栏自己展开到「执行过程」（`trace/install.ts` 的 `installAutoOpen`，听的是引擎给的「这一轮开始了」）。一个对话只自己打开一次：之后人把它收起来，这个对话里不再自己打开，换一个对话照样会开；窗口窄于 768 时引擎会把右边栏铺满窗口盖住对话，这时不开。打开、收起都照引擎原样：右边栏从对话区里让出一列，点右边栏顶上的「收起右侧边栏」收回去。引擎默认第一次打开占窗口的 45%（1280 的窗口里对话区从 1000 被挤到 424），所以第一次打开的宽度改成 420（`ui/client/rightpane.ts`，存宽度的动作不在引擎公开的接口上，挂在 `ctx.layout.panels.setRightbar`；**引擎升级后对着 `dsh-client-ui-layout` 重新核一遍**）。窗口不够宽时引擎给对话区至少留 400，右边栏会比 420 窄。所以主窗口一开始就开宽一点（2026-10-21，用户说的：默认就把窗口开宽，不用每次打开再加宽）：1480×820，左栏 280、对话区 780 上下、右边栏 420；屏幕放不下时取鼠标所在那块屏幕能用的范围减去 40 的留边（`desktop/size.cjs`，`size.test.mjs` 里有 1920 的 100%、125%、150% 和 1366 几种）。原来固定是 1280×820，右边栏展开时对话区只剩 580。真程序在开发机（2560×1392 能用，缩放 150%）上开出来是 1481×822，居中。窗口尺寸不记住，每次照这个开。

2026-10-12 到 10-21 之间，右边栏打开时窗口还会向右加宽、收起时缩回去，中间的对话不被挤窄（页面 `rightpane.ts` 读引擎框架上的列宽报给壳，壳 `desktop/pane.cjs` 拉宽窗口；为了这一两帧里对话不被挤一下，页面先把引擎的框架钉宽，等窗口到位再放开，`style.css` 里另有一段关掉引擎自己的滑动）。用户 10-21 说这块特别容易出 bug、经常碰到渲染问题，要求直接去掉、走正常逻辑。窗口加宽、钉框架、`campus:side-pane` 通道和那段样式都删了。验证：在隔离引擎里发一条消息，右边栏自己展开，页面宽度等于窗口宽度、没有钉框架；点收起后收回，同一个对话再发一条不再自己打开。

**图是长出来的**（2026-10-12 用户说的：现在是直接冒出来的，要像树一样生长）。一行接一行往下长，隔 80 毫秒一行（`TraceTab.tsx` 的 `useGrowth`）：一行出现时，它自己从没有高度长到一行高，把下面的行慢慢推下去；线沿着走向画过去（长度归成 1，虚线的偏移从 1 走到 0）；线画到了，圆点才弹出来；字最后淡进来。线是按同一个速度画的，主线一行正好画一步那么久，所以上一行画到底、下一行正好接上，看着是一根线一直往下长；每一段线等多久、画多久写在 `style.css`「长出来」一段的注释里。几件要记着的事：放出下一行认的是行的身份不是个数（中间插进来一行时，下面已经在的行不会被收回去重长一遍）；一下子多出来很多行（刚打开页签、点开更早的一轮）时一次长几行，整张图在一秒上下长完；一行早就在了、后来才多出来的线（下面又接了一站）不排队，马上画，排不排队在线挂上去的那一刻定下来之后不变（画到一半改延时会跳一下）；系统设了减少动效时全部直接出现。

**长过的不再长**（2026-10-12 用户发现的：有时候整条路径会从头重放一遍）。原因在引擎那边：右边栏页签的正文只在它看得见的时候才挂着，切到右边栏的另一个页签（比如助手交付文件时自己打开的预览）、换一个对话、打开设置或插件、学习这样占满中间的页面，正文都会被整个卸掉，回来是重新挂一遍（引擎 dockkit 的写法，页签类型没写 `keepMounted` 的都这样；只是把右边栏收起来不卸）。而「哪些行已经长出来了」原来记在组件里，出场的动效又是挂上去时放的，所以每回来一次整张图就从头再长一遍。现在长过的行按「哪个对话的第几轮」记在页签外面（`trace/grown.ts`，只在应用开着的这段时间里记着，留最近 200 轮）：回来时长过的行直接摆好（行上带 `data-quiet`，`style.css` 里对它关掉出场动效），只有离开的这段时间里新多出来的行接着长；重开应用以后第一次打开、第一次点开更早的一轮，照旧长一遍。没有改用 `keepMounted`：正文是留住了，但引擎用 `display: none` 藏它，再露出来时所有行的动效会同时重放一遍，而且每个看过的对话都要一直挂着一份。

**本地操作失败了也标出来**（2026-10-12 用户要的；之前的说法是「本地操作偶尔出错是常事，不标」）。一条命令被对话的权限拦住、助手转头换了个办法，或者第一次读文档缺环境、装好再读一遍，图上都看不出中间失败过。现在失败的本地操作和网站那边一样：圆点画成同样大的红点，行尾写「失败」，这一行不再是淡的，点开有原因。成没成按这一次调用是哪一种来看（`parse.ts` 的 `outcomeOf`）：校园命令看输出的 JSON 信封，不访问网站的那几个模块（读文档、看本地档案）也一样，以前它们只看引擎的出错标记；别的命令行和对话里那张命令卡片一个看法（引擎 `dsh-shell` 的 `parseExitStatus`），退出码不是 0、被信号杀掉、超时被停掉都是没成功，因为命令退出码不是 0 时引擎并不算它出错，只在输出最后写一行 `[exit code: N]`；引擎自带的工具（读写文件、查找、联网）只看引擎的出错标记。原因取命令自己写到 stderr 的第一句；被对话的权限拦住的（结果里有 `[sandbox: file access denied …]`）前面加一句「对话的权限不让读写这个位置」。对着 2026-10-12 的两次真实对话核过：往 D 盘根目录写文件被拦住的那条 `Set-Content`，和读作业附件时缺环境的 `doc text`、目录不存在的 `glob`。

**把正在做的一行带进视野，只滚这张图自己**（2026-10-12 用户遇到的：问一句，右边栏自己打开；把它收起来再问一句，对话整个被推到左边，右边空出一块，之后也不回来）。对话进行时新的一行出现，要把正在做的那一行带进视野，原来用的是 `scrollIntoView`，它会把所有能滚的上级一起滚。右边栏收起时这张图还挂着，只是被引擎挪到了框架右边的外面（`transform` 挪出去、`visibility: hidden`，框架是 `overflow: hidden`）；`scrollIntoView` 为了让那一行露出来，把引擎的整个框架横着滚过去一个右边栏那么宽。现在不用它，`TraceTab.tsx` 的 `reveal` 只改这张图自己的 `scrollTop`，够露出那一行就停；行刚出现时还在从零长高，按一整行的高度留位置。连带改了一处：`.campus-trace` 现在自己是能上下滚的那一层（`height: 100%`、`overflow: hidden auto`）。引擎装页签正文的那一层是 `overflow: hidden`、和右边栏一样高，以前这张图不自己滚，步骤多到一屏放不下时下面的行被裁掉，滚轮滚不到，只靠新的一行出现时那一下自动滚。在隔离实例里接了一个本机的假模型服务照原样走过：没改之前收起再问一句，框架的 `scrollLeft` 从 0 变成 420；改了以后一直是 0，右边栏开着、收起两种情况下跑一轮二十多步的慢命令，图自己的 `scrollTop` 都跟着往下走，正在做的那一行下面留着一行的位置。

代码在 `ui/client/trace/`，页签本身是 `ui/client/TraceTab.tsx`：

- `model.ts`：数据从哪来。向引擎的 `uiConversation` 登记两个 Definition（工具调用、用户的提问）和一个 View，引擎按会话把事件喂过来，对话进行时实时更新；页签用 `uiConversation.binding(sessionId).target('campus-trace')` 订阅。写法照引擎自己的 `ui-tool/todo-history`。
- `parse.ts`：把一次调用翻成人话。会话里的校园命令是 `pwsh` 加一整条命令，从里面认出 `zju.ts` 后面的「模块 对象 动作」；网站的名字在 `sites.ts`。
- `steps.ts`：每一步叫什么。把一条命令说成助手正在做的一件事，动词开头、十个字上下（「查教学班的老师、时间和余量」「查老师的评分和学生评价」）：太短看不出在干什么，照搬命令说明又一行放不下（2026-10-11 用户定的：这页的用处就是把看不懂的命令变成看得懂的过程）。成对的命令加 `--cancel` 时另起名字。`commands.gen.ts`（由 `gen-commands.mjs` 从命令树生成）只用来认命令，和没起名字时拿说明的第一句顶着。core 加、改、删了命令：运行 `node ui/client/trace/gen-commands.mjs` 重新生成，再在 `steps.ts` 里补上或删掉名字，`npm run test:trace` 两样都查。
- `grown.ts`：哪些行已经长出来过，记在页签外面（见上面「长过的不再长」）。
- `route.ts`：怎么拼成路线。引擎只记了「轮 → 步 → 同一步里并行的调用」，没有谁依赖谁，所以只按这个画：一次调用一站；同一步里发出的几次调用是同一个岔口的几条支线；下一步的调用能各自接上（先找最后一站是同一种动作的支线，再找同一个网站的，接在它下面，一条支线只接一次）就接，有一次接不上就另起岔口；读写文件、跑脚本这些本地操作一次一站排在主线上，夹在中间时把前后的支线隔开。岔口里靠上的支线接着做时，新的一行会插在中间，所以岔口里的几行不严格按时间排。

行尾能显示多少取决于命令的输出：输出完整时数出条数、取前几条标题；输出太长被引擎截掉开头，或者模型把输出导进了文件，行尾就空着。校园命令末尾的 `[exit code: N]` 不拿来判断成败（PowerShell 里命令只要往 stderr 写过东西，成功了也是 1），看的是信封里的 `ok`；别的命令行没有信封，只能看它。实际访问了哪些主机现在不知道，网站名是按模块对的。

## 读文档

2026-10-12 改的。原来读 PDF、Word、PPT、Excel 全靠 `zju doc`，它的取文字、转 PDF、取页、渲染都是 Python 写的，要先跑 `zju doc setup`（`python -m venv` 加联网装包）。应用不带 Python，所以在没有 Python 的电脑上这条路是坏的；开发机的真实数据目录里它也一直是没装好的（`doc check` 返回 `ready: false`），只是之前没人让助手读过文件。现在分成两条路，都不用 Python：

- **要文字**：`zju doc text`。PDF 用 pdf.js 逐页取文字层；Word 让引擎自带的 Office 引擎直接导出纯文本；Excel、PPT 先让它转成 PDF 再逐页取。带着校园登录去下载链接上的附件（教务网会话、校内和 CC98 走 WebVPN）还是它做，这一段没动。
- **要看页面长什么样**（版面、公式、图表、扫描件、截图做的课件）：不经 `zju doc`，助手直接用引擎自带的 Office 引擎的命令行把页面渲染成 PNG，再用 `read_image` 看。用户的意思是：引擎已经带着 LibreOffice，现在的模型又都能看图，没必要在我们这边再包一层。

`zju doc` 因此从 8 条命令缩到 4 条：`text`、`find`（按关键词找页）、`pdf`（照片、Word、PDF 合成一份，交作业用）、`pages`（取页）。去掉的是 `render`、`images`、`check`、`setup`，没有留别名。代码在 `core/zju/lib/doc/`，细节见那里的 README：

- 新加两个纯 JS 的库，装在 `core/zju/node_modules`：`pdfjs-dist`（取文字，带中文 PDF 要的 cMap）和 `pdf-lib`（合成、取页）。安装时带 `--omit=optional`（`npm install --prefix core/zju --omit=optional`），不要 pdf.js 渲染用的 `@napi-rs/canvas`。打包时排除了它们用不到的部分（`package.json` 的 `build.files`：pdf.js 的 `build`、`web`，pdf-lib 的 `dist`、`es`、`src`、`ts3.4`）。
- Office 引擎（`@deepseek-ai/libreoffice-kit`）和图片库（`sharp`）是引擎的依赖，已经在安装包里，`core/zju` 按包名直接引用应用根目录 `node_modules` 里的那一份。图片进 PDF 之前用 sharp 按拍摄方向转正。
- 和原来不一样的地方：Excel 取出来的文字是按打印的页分的，不再一个工作表一页、格子之间也没有竖线；RTF 和 WPS 引擎不认，照实返回 `unsupported`；取 PDF 里嵌入的原图没有对应的做法了，要图就渲染整页。

**把引擎的 Office 命令行交给助手**（`ui/profile/office.mjs`）。引擎自己只拿这个引擎给右边栏的预览用，给模型用的那套 office 技能（`dsh-skill-office`）在我们的组合里没有挂，助手原先不知道有它。现在每次对话的上下文里多一段「看文件」（`campus-files`）：给出命令行的完整路径（随安装位置变，所以不写在 `AGENT.md` 里）和两种用法，`render --input 文件 --output-dir 新文件夹 --pages 1,2,3` 和 `convert --input 文件 --output 结果.pdf`。页码只认逗号分开的写法。它是助手自己起的命令，在沙箱里跑：在隔离的引擎里实测过，默认的「工作区内修改」下渲染 PDF、渲染 Word、Word 转 PDF 都能跑（各一秒上下，输出落在对话文件夹里）；「仅可查看」下写不了输出，报的是引擎标准的沙箱拒绝。所以没有把它列进不进沙箱的名单。

验证：`npm run test:core`（`core/zju/tests/doc.test.ts` 五项：按文件头认格式、页码规则、各种格式取文字、Word 走引擎、合成和取页和找关键词；照片带方向标记时转成竖的这一条是量 PDF 页面大小核的）。命令行上实际跑过四条命令，中文文件名、扩展名不对的文件、带透明底的截图都试了；合成出来的 PDF 用引擎渲染成图看过，照片是正的。pdf.js 在系统的 Node 和应用自己的 Node 上都取得到中文。PPT 用真实的课件试过：一份老的 `.ppt` 取出 14 页文字；一份全是截图的 `.pptx`（134 页）照实返回 `no_text`，用引擎渲染得出图。应用里也走过一遍：只起引擎（隔离的数据目录、真的模型），让助手读那份 `.ppt` 的文字、再看那份截图课件的第 5 页，它依次读了技能说明、跑 `doc text`、用「看文件」里的命令渲染、`read_image` 看图，13 秒答完，内容是对的；同一个引擎里核对了微信公众号默认关（关着时壳拒绝读本机）、打开以后经应用自己的 Node 读到本机的 94 个号。0.1.4 发版前在打出来的成品里（`dist/win-unpacked`，用成品自己的程序当 Node）又跑了一遍：读 PDF、读 Word、读老格式 PPT（14 页）、照片加截图加 Word 加 PDF 合成、取页、找关键词、用引擎的 Office 命令行渲染一页，都通；`build.files` 里那几条排除没有排错，成品里从 `core/zju` 引用根目录的 Office 引擎和 sharp 也找得到。**没验证的**：Excel 走引擎这一条（手头没有样本文件，只有引擎自己声明支持）。

**场馆预约的验证码交给模型认**（2026-10-12，用户定的：和微信公众号一样交给模型；走引擎的模型服务，登录 ChatGPT 的也要能用）。这原来是最后一处要 Python 的：一套本地识别模型（ddddocr、PaddleOCR、PaddlePaddle，装好 893 MB），要 `tyys venue setup` 建环境。`scripts/tyys/captcha.py`、`tyys venue setup`、`tyys venue check` 删了，没有留别名。到这里应用里没有功能需要 Python。

- **模型是用户现在选的那一个**，不另要 Key。校园命令是引擎启动的另一个进程，够不着引擎的模型服务，所以加了一条管道：引擎进程一启动就把地址放进 `CAMPUS_MODEL_ENDPOINT`（`desktop/host.mjs`），在 `ui/profile/vision.mjs` 听着；命令（`core/zju/lib/tyys/captcha.ts`）把题目和图交过来，引擎用 `ui/profile/model.mjs` 问一次再把回答还回去。`model.mjs` 因此会带图了：引擎的模型服务不直接收图，要先存进附件库再引用，问完就删。思考开到这个模型最低的一档；选的模型看不了图、应用里没配好模型时，命令报的是要用户去设置里处理。
- **照搬微信公众号那边的问法不行**：拿真实题目去场馆校验，6 道只过 3 道，字认对了，坐标偏几十像素。题图只有 310×155，要先放大三倍；再让模型把图里的字全认一遍，题目里的三个字各认出一个才作答，认不齐就换一道题；不开思考。直接调 DeepSeek 接口时，这样取 9 道，8 道作答全部通过，1 道换题。旧的本地识别在同一类题上每道约三秒，14 道里 3 道解不出。各种问法的对照在 `core/zju/lib/tyys/README.md` 的「验证码识别」。
- **走引擎以后复测过**（隔离的引擎，DeepSeek）：存下的 20 道题跑两遍，作答的里面各有 15 道三个点都在 10 像素内；真实题目 4 道，3 道作答全部通过，1 道换题；一般一秒上下，两遍里各有一道等了十几秒，原因没查。
- 场馆对取验证码有次数限制，测试时碰到了（约 12 分钟取 29 道以后被拒，约六分钟后恢复），所以一次预约最多取三道。
- 验证：`npm run test:core` 里 `tyys-captcha.test.ts` 八项，`npm run test:profile` 里 `vision.test.mjs` 五项，模型都是假的。**没验证的**：登录 ChatGPT 时用 GPT 认得准不准、要等多久（这台机器上没有登录着的 ChatGPT 账号）；改完以后的一次真实预约（预下单、验证码、提交连起来）；在打开的应用里由助手跑预约时命令读不读得到 `CAMPUS_MODEL_ENDPOINT`；装好的应用。

## 智云的转写和文件落点

2026-10-09 改的，代码在 `core/zju/lib/zhiyun/`：`asr.ts`（转写）、`places.ts`（落点）、`courseware.ts`（课件提取，从原 `asr.ts` 里挪出来，没改）。

**转写不再用 Python。** `zhiyun trans audio` 原来要 uv、Python 3.12、CUDA 版 PyTorch 和 funasr，现在用引擎「语音输入」插件带的那一套：SenseVoiceSmall 的 ONNX int8 权重，经 `sherpa-onnx-node` 在 CPU 上跑。运行库已经随应用打包；模型（约 240 MB）在 `%APPDATA%\CampusAgent\home\speech-to-text\sensevoice\models`，和语音输入共用，谁先用谁下载。第一次转写时 core 自己下：清单（地址、大小、SHA-256）读插件包里的 `runtime/assets.json`，`huggingface.co` 和 `hf-mirror.com` 哪个先回应用哪个，校验通过才换成正式文件名。`zhiyun setup --component asr` 只做这一件事，`check` 只看不下。原来的 `worker.py`、`setup_models.py`、FireRed 引擎和 `--engine`、`--device`、`--batch-seconds`、`--cpu`、`ZJU_ASR_*` 都删了。

插件自己的接口（`ctx.speechToText`）转不了整节课：一段录音限 4 MB，只返回一整段文字、没有时间。所以只借它的运行库和模型，识别流程是我们自己的。

断句的设置不能照搬插件的。拿一节 148 分钟的录播（ADS《优先队列》）在本机（Ryzen 9 9950X3D、RTX 5080）比过，没有人工校对稿，用智云官方字幕当第三方参照：

| 版本 | 耗时 | 和官方字幕的差异 | 官方有、它漏掉的字 |
|---|---|---|---|
| 原来的 PyTorch 版，GPU | 51 秒 | 10.28% | 544 |
| 原来的 PyTorch 版，CPU | 163 秒 | 10.27% | 552 |
| ONNX int8，插件原样的断句 | 106 秒 | 12.29% | 1358 |
| ONNX int8，现在的做法 | 113 秒 | 10.52% | 546 |

插件的断句是给几秒钟的语音输入用的，切得碎（1719 段），每段单独识别会丢句首句尾的字。现在的做法是把相邻的段并成不超过 15 秒的一块、两头各留 0.3 秒、断句阈值从 0.5 放到 0.3，这组数写在 `asr.ts` 的 `RECIPE` 上。同样设置下 fp32 权重（938 MB）和 int8 没有差别。和 PyTorch 版剩下的差距是同音字；专业词三家都错（「摊还」都写成「瘫痪」），对照课件校正这一步省不掉。应用里的命令跑出来的结果和这次实测的那一份逐字相同。

**文件放进「文档」。** 智云下载和转写的结果原来在 `%APPDATA%\CampusAgent\zju\output`，用户找不到，现在：

```text
文档\CampusAgent\
  课程\<课程名>\第N次 日期\     zhiyun download：materials\、slides\、subtitles.json/txt、video.mp4、download.json
    转写\<文件名>\              这次课里的文件转出来的文字
  转写\<文件名>\                别处的录音、课件转出来的文字
```

一次课一个文件夹，各带自己的清单，分几次下不同的课次互不相干。`CAMPUS_CHATS_DIR` 把 `文档\CampusAgent` 整个换掉（和对话文件夹同一个开关，测试时一定要设）。指定 `--out-dir` 时还是原来的布局，Learning 往主题的 `data\` 里下载不受影响。转写时转出来的那份 16 kHz 音频（一节课近 300 MB）用完就删。顺带修了一处：所选课次里有一次课还没有字幕时，整条下载命令会报错，现在那次课记进 `skipped`。别的模块（学在、超星、知网、CC98）的下载位置没动。

没做和没验证的：

- FFmpeg 已随应用带上（见下一小节），但没有重新打包，也没有在打开的应用里让助手实际转一次。
- `zhiyun trans ppt`（从课件里提取文字和原图）2026-10-12 删掉了，连同它的 Python 环境：模型能看图，课件用 `doc text` 取文字或把页面渲染成图来读（见「读文档」）。
- 只测了这一节课、这一台机器；普通笔记本上的速度没测，打包后的应用里没跑过。
- 学习页当时还是占位，后来做了，见「学习」一节。

引擎升级后核对三样：包名 `@deepseek-ai/dsh-experimental-speech-to-text-sensevoice`、它的 `runtime/assets.json` 的结构、模型目录的布局（`models/sensevoice-onnx/`、`models/silero/`）。

### 自带的 FFmpeg

录音转格式、合并回放要用 FFmpeg。原来靠 `zhiyun setup --component media` 用 npm 临时装，打包后的应用里没有 npm，装不上。2026-10-09 起它是应用的依赖：根目录 `package.json` 里的 `ffmpeg-static`（锁在 5.3.0，和 core 的 `setup` 原来装的是同一个版本），装包时下好当前系统的那一份（Windows 上是 `node_modules\ffmpeg-static\ffmpeg.exe`，约 83 MB），打包时跟着 `node_modules` 进安装目录。

ZJU Core 没有为这件事改代码，它本来就认环境变量 `FFMPEG_PATH`。壳启动引擎时把自带的那一份的路径放进去（`desktop/ffmpeg.cjs`，在 `desktop/main.cjs` 起引擎的那一行接上），引擎启动的命令和应用自己跑的 core 命令都会继承。用户自己设了 `FFMPEG_PATH` 的以用户的为准。`desktop/ffmpeg.test.mjs` 核对这一份在、跑得起来，并入了 `npm run test:plugins`。

这份 FFmpeg 是 gyan.dev 的 6.1.1 essentials 构建，GPL v3；`ffmpeg-static` 这个包是 GPL-3.0-or-later。应用只把它当一个单独的程序调用，许可证文本（`ffmpeg.exe.LICENSE`）和说明跟着二进制一起分发。交材料时在第三方组件里列上它。

### 给命令行用的 Node

2026-10-11 加的，0.1.3 起有。技能里的命令都是 `node …`（`core/zju/SKILL.md` 的 `node <SKILL>/scripts/zju.ts`、`core/learn/references/animation.md` 的 `node engine/build.mjs`），由引擎的命令行工具在用户的机器上执行，找的是 PATH 上名叫 `node` 的程序。最初复用了 Electron 的 Node 模式；2026-11-01 更新后随包提供独立 Node 24.19.0，避免引擎原生加载器与 Electron 的 V8 版本耦合。用户无需安装 Node.js，Core、引擎与技能子命令使用随包运行时。

做法在 `desktop/node.cjs`：壳启动引擎时明确使用 `node_modules/node-win-x64/bin/node.exe`，在数据目录的 `bin` 文件夹（`%APPDATA%\CampusAgent\bin`）里放一个 `node.cmd`，它调用同一运行时，参数原样传过去；再把这个文件夹放到交给引擎的 PATH **最前面**（在 `desktop/main.cjs` 起引擎的那一行接上），引擎启动的命令都会继承。几个定下来的地方：

- 放在最前面，系统里已经有 Node 的也用我们这一份：要的是所有机器上跑技能的是同一份 Node，用户自己装的可能太旧。开发时（`npm start`）也一样，免得只在装好的应用里才出问题。
- 应用的可执行文件在哪，不写进 `node.cmd`，经环境变量 `CAMPUS_NODE_EXE` 告诉它：`.cmd` 是按系统的代码页读的，用户名带中文时写在文件里的路径会读错，环境变量不会。文件本身全是 ASCII。
- 只放 `.cmd`，不放 `.ps1`：PowerShell 会先找 `.ps1`，而系统默认不许运行脚本，那样 `node` 反而整个用不了。
- 只做了 Windows 的。没有给 `npm`：技能日常用不到，讲解要加别的画面库时才用（`animation.md` 里的 `npm install --prefix lessons/<主题>/film/build/vendor`，装在这一集自己的文件夹里），那时仍然要用户自己有 npm。

验证：`desktop/node.test.mjs` 四项，并入了 `npm run test:plugins`。测试起一个 PATH 里没有 Node.js 的 PowerShell，数据目录带中文和空格，在里面敲 `node`：版本与随包运行时一致，`.ts` 能直接跑，带空格和中文的参数原样到，退出码传得回来，脚本里用 `process.execPath` 再起的子进程也是 Node。另核对引擎的原生加载器可用、运行时缺失明确失败，以及子进程继承 PATH 和 `CAMPUS_NODE_EXE`。**没验证的：在一台真的没装 Node.js 的电脑上让助手跑一条校园命令**（开发机上装着 Node，只能把它从 PATH 里拿掉来模拟）。

## 留下来的东西怎么分

应用里会留下来的资料按「说的是谁」分四样，各放各的地方：

| | 说的是 | 谁写 | 助手怎么用 | 在哪看 | 存在哪 |
|---|---|---|---|---|---|
| 基础信息 | 用户（学校登记的） | 用户填，或从教务网读 | 每次对话都带 | 设置 → 个人档案 | `identity.json` |
| 记忆 | 用户（学过什么、偏好、目标、背景） | 对话结束后应用回看一遍自己整理；用户明说「记住」时助手当场记；用户能改能删 | 每次对话带目录，全文按需读 | 设置 → 个人档案 | `memory/*.md` |
| 备忘录 | 一件事（比赛、要办的手续） | 用户写，或用户让助手记 | 用户问到才查 | 校园事务页左栏 | `notes/*.md` |
| 技能 | 助手怎么做一件事 | 应用自带几个（开发写的）；用户让存、或走通以后，助手照「写技能」写 | 遇到同类问题时加载 | 插件页第三组 | 自带的在 `core/skills/<名字>/`，助手写的在 `skills/<名字>/` |
| 工作流的补充 | 照自带的工作流办事时学到、正文里没有的一条 | 对话结束后应用整理 | 加载 zju 技能时拼在正文末尾 | 插件页第三组 | `flow-notes.json` |

记忆和备忘录的分界：主语是用户这个人的进记忆，主语是一件事的进备忘录。记忆不用用户开口，但也不由对话里的助手顺手记，而是对话结束后统一整理（见下一节）；备忘录助手不主动写。外面发来的通知是另一类，谁也不写，看过就过去，放在校园事务页右栏；其中要留下的，用户在那一行点一下加进备忘录（2026-10-12 加的，见「通知加到备忘录」）。

2026-10-09 之前前两样和备忘混在一起，叫「档案笔记」，放在侧栏的「个人档案」页。用户定的改法：基础信息和记忆进设置（填一次以后很少再看），备忘录和通知并进校园事务，技能进插件页，侧栏的「个人档案」一项拿掉。

侧栏固定四项：插件、自动化任务、校园事务、学习。**不再往侧栏加入口**（用户的原话：侧边入口多了会无限延长），新的内容放进已有的页面里，用分栏、分块或页内切换。自动化任务是引擎的定时任务插件自己登记的，排序号是 10；我们自己的两项在 `ui/client/panels.tsx` 里用 30、40，不能和它相同，否则谁先加载谁在前。

## 对话后复盘

2026-10-12 做的。用户要的是：助手能不断长进，又不能攒一堆垃圾。在这之前写不写只靠对话里的助手自觉（`AGENT.md` 一句话加两个工具的说明），真实使用里它只主动写过一条记忆，内容还是「这门课的作业怎么交」这种随时能查的。

做法参照 Hermes Agent 的结构（什么时候写、写到哪、怎么清各有各的机制：它是回答发出去以后另起一个分身回看对话，记忆有硬上限，技能记用量、到期归档），力度反过来。它的复盘提示要求积极写，面对的是做多步工程的开发者；我们多数对话是查课表、查成绩，照那个力度写出来的就是垃圾。所以这里**默认不写，有信号才写**。

- **对话里的助手不再主动写记忆**。只在两种时候用 `campus_profile_write`：用户明说让它记住关于他本人的事；技能里写明要记的那一步（learn 做完讲解补一行「看过的讲解」）。改在 `core/AGENT.md`、工具的说明和 `core/zju/SKILL.md` 里。
- **什么时候跑**。一轮结束后十分钟没有新的一轮，就复盘这个对话（`ui/profile/review.mjs` 听引擎的 `session/event`，`turn/end` 开始计时，`turn/start` 取消）。同一个对话后来又聊了，再复盘时只把新的几轮完整给模型，前面的只留用户说过的话。子智能体的会话、没有人发言的会话不看。一次只跑一个。
- **问模型一次，它只出建议**。把会话压成摘要（`review-digest.mjs`：用户的话、助手的回答、每次调用和成没成），连同已有的记忆全文、自带的工作流全文一起问（`review-prompt.mjs`，用 `model.mjs` 的 `askModel`，低档思考）。规矩和工作流放在系统提示里，能走模型的前缀缓存：一次约五千 token，四千多是缓存里读的，多数一到九秒。
- **只做两类**。记忆，和工作流的补充。新建技能的建议这一期不产生，`campus_skill_save` 照旧。
- **记忆的条目固定成四类**：一门课一条（标题是课程名，小标题用 learn 定的「学过」「还不熟」；「看过的讲解」是 learn 自己记的，复盘不碰）、「讲解偏好」、「目标与打算」、「个人背景」。条数因此有天然的上限。
- **代码把关**（`review.mjs` 的 `vet`）。模型的建议不能全信，离线试的时候它会把助手讲的话写成用户懂了什么、误删没有矛盾的旧行、往依据里抄敏感的话。所以：
  - 依据必须是这次对话里用户原话的一部分。依据只用来核对，不落盘，也不进日志。
  - 写下的每一行还要和用户说过的话对得上（至少三处两个字连着一样）。助手讲的内容、模型自己发挥的，和用户的话重合不了几个字。
  - 放宽确认的话（「以后不用问我」「直接提交」）一律不写，哪怕用户真说过：要不要先问由应用的权限设置管，不能经复盘变成记忆或者工作流的一步。
  - 类别只能是那四类。课程名先对已有的课程条目（名字一样，或者简称只对上一门），再对他上过的课（学习页缓存里智云的课程表，`learning.mjs` 的 `courseTitles`），都对不上不新建，新建时用正式的课名；标题是别的记忆的不能当课程；已归档的不动。
  - 一次对话最多两条记忆、一条工作流补充；一条记忆一次最多加三行，一行最多 160 个字；一条记忆的正文到 3000 字就不再加。
  - 删除只认一种：这条记忆是助手写的、没人改过，被删的是「还不熟」下面原样的一行，同一条建议里有一行加到「学过」并且带着这一行的字（他说整个这一点会了，挪过去）。只懂了一部分的不删。别的删除一律不做。
  - 有人改过的记忆不动原文，只在末尾「助手补充」下面加。
  - 工作流补充：目标是 `core/skills/` 里真有的技能；只收用户纠正出来的（要有用户的原话作依据，补的那一条要和他说的对得上），助手自己试出来的不收；对话里至少有两条成功的、这个工作流正文里出现过的命令；和已有的补充、和正文都不重复；一个工作流最多八条。
- **写了要让人看见、能撤**。每处改动记一条日志（档案目录的 `review-log.json`：什么时候、哪次对话、改了哪条、加了什么、改之前的全文）。设置的「个人档案」里多了「自动整理」一块（`ui/client/ReviewSettings.tsx`）：一个开关，和最近整理的列表，每条能撤销。同一条记忆整理过几次的，从最近一次往回撤。之后又被人改过的记忆不撤，页面上那一行显示「后来改过」，日志里改之前的全文也不再留。撤销过的行不会被再写回来。没过核对的建议和原因、模型没问成的原因记在缓存目录的 `review.json` 里，查问题时看。
- **工作流的补充**（`ui/profile/flow-notes.mjs`）。用户指出技能还包括之前的工作流（比如选课）。工作流在安装目录里，升级就换掉，使用中不能改；补充存在档案目录，拼在 zju 技能正文的末尾交给引擎（`skills.mjs` 里技能的正文是我们给的），助手加载 zju 时就看到。每条记着写下它时工作流文件的指纹，应用升级后正文变了就标成「待核对」。插件页「技能」一组里，每个工作流是一项自带的技能，补充接在它的正文后面，点开看、能把这几条整个删掉（见「校园插件」里的「自带的技能」）；单条的在「个人档案」里撤销。设想的路是「学到的 → 工作流的补充 → 开发整理进工作流正文 → 做成命令」，往上走一层就从下面拿掉。

怎么定下来的：先离线试。把真实数据目录里的七次对话和二十多条造的对话交给模型复盘，再让另一个模型独立检查，照挑出来的毛病改规矩，一共三稿。第一稿高档思考反而更爱多写；第二稿把记忆的条目固定成几类以后，新建条目的标题才稳定下来。正式实现以后又让它查了两轮：头一轮挑出一处会丢内容的查重（「学过」要加的那一行和「还不熟」里要删的那一行一样时，这个知识点会从记忆里消失），和几处靠模型自觉、代码拦不住的口子（工作流的补充最松：只要对话里有一次成功的校园命令就能写），上面那几道核对里有一半是照这一轮收紧的。

验证：`npm run test:profile`（`review.test.mjs` 九项：摘要、提示、核对记忆、核对课程名、核对工作流的补充、落盘和撤销、小标题下面加行、什么时候跑、模型问不成；`flow-notes.test.mjs` 三项；`host.test.mjs` 里接线的几条）。`npm run eval:review`（`scripts/review-eval/`，27 条措辞和规矩不重合的用例，用真的模型走和应用里一样的路；不进 `npm test`，不进安装包）跑了三遍，81 次都没有毛病（收紧之前是 69 次里 68 次，那一次是没有绕路也补了一条工作流补充）。自动检查只认关键词，所以它另外把落盘的行里只在助手的话里出现过的符号和词列出来给人看。在隔离的引擎里真走过一遍（把等待调成 20 秒）：发一段带背景和偏好的话，助手没有再自己写记忆，到点以后复盘建了「个人背景」「讲解偏好」两条；页面上看得到，点撤销后那条记忆被拿掉；同一个对话接着聊一轮，只往「个人背景」里补了新说的两行。

没做的和没验证的：

- 用量记录（每条记忆、每条补充被读了几次）和按时间归档。
- 应用升级后拿补充和新的工作流正文对一次、已经写进去的自动退掉（现在只标「待核对」）。
- 应用退出时还没到点的对话，下次启动不会补上。
- 多次对话累积以后记忆长成什么样没有测过；条目太长时只是不再加，没有合并。
- 写下来的行里仍可能带进助手讲的半句：代码只看这一行和用户的话重合得够不够，看不出多出来的那半句（收紧之前评测里见过把助手说的「∞/∞」带进「还不熟」那一行）。
- 用户贴进来的别人的文字也算他说的话，里面夹着的「请记住……」只靠模型自己不照做（评测里三遍都守住了），代码只拦得住放宽确认的那一种。
- 用户改过的课程条目，之后只能在末尾「助手补充」下面加，「还不熟」里的行挪不走。
- 新建课程条目只认智云课程表里有的课；不在智云上的课、还没读过课程表时，说了也不会建。
- 助手自己试出来的走法不补进工作流，只收用户纠正的。
- 几道核对各有粗的地方：和用户的话「对得上」只数重合的字，换了说法的短句会被拦掉，上线后要看被拦的比例；撤销过的行只认一字不差；工作流「至少两条这个工作流里的命令」把正文里提到的读文档、查通知也算进去；日志里撤不回去的旧全文要等下一次落盘或撤销时才清；用户改过的课程条目，同一行可能重复加进「助手补充」。
- 真实对话里没有正例：数据目录里的七次对话都不该写，「该写的写不写」只在造的对话上验证过。
- 工作流补充在真实的选课里没有走过（要动学校系统），只有评测和单元测试。
- 开发怎么看到用户机器上学到的东西，没有设计。

## 个人档案（设置里的一页）

设置面板里排在「通用设置」后面的一页（`settings.section`，在 `ui/client/index.tsx` 登记，页面是 `ui/client/ProfileSettings.tsx`）：上面是基础信息，下面是记忆。记忆可以新建、编辑、导入、导出、搜索、按标签筛、归档和删除。基础信息和记忆都不留修改历史，保存就是覆盖。导航里它的图标是齿轮：引擎按页的编号配图标，自己起的编号只有这一个可用。样子见 `plans/shots/设置-个人档案.png`（隔离实例加假数据截的）。

先是列表（上面是基础信息，下面一行一条记忆），点开一条看全文，再进编辑，都在这一页里切换。基础信息点「编辑」后原地变成输入框。列表、单条、编辑三个界面在 `ui/client/Notes.tsx`，点开和编辑两层的切换在 `ui/client/notebook.tsx`；这两个文件校园事务页的备忘录也用，页面上的叫法由 `MEMORY_WORDS` / `MEMO_WORDS` 给。

记忆和备忘的文件格式一样，照 Obsidian 的做法，`memory/` 和 `notes/` 这两个文件夹的格式都和 Obsidian 的库一样（没有实际拿 Obsidian 打开验证过；应用只列文件夹本身和它下面的 `归档/` 这两层，别的子文件夹里的不会列出来）：

- 一条是一个 Markdown 文件，文件名就是标题，所以同一处标题不能重名，也不能有 `\ / : * ? " < > | [ ] # ^`。改标题就是改文件名，同一处别的几条里指向它的 `[[双链]]` 跟着改。
- 文件开头两行 `---` 之间是属性区：`tags` 是标签，别的每行一项「名称: 值」（学期、来源这类）。文件里没有谁写的、什么时候写的这类记录，改动时间用文件自己的。
- 正文是普通 Markdown。`[[标题]]`、`[[标题|显示的字]]` 链到同一处的另一条；页面上把它交给引擎当文件链接画（`Notes.tsx` 的 `withLinks`），点了打开那一条，还没有就按这个标题新建。
- 归档是把文件挪进那个文件夹下面的 `归档/`，取消归档再挪回来。
- 在别的编辑器里改过的照样读。属性区写坏了的也列出来并标明，打开编辑时给的是整篇原文，改好再存。

记忆这一块在页面上的规矩：

- 列表：新建和导入在「记忆」标题那一行；下面是搜索，有归档的时左边多一个「记忆 / 已归档」的切换；再下面是写明「标签」的一排标签筛选。一行只有标题和最近改动的日期，标签不跟在标题后面。
- 单条：标题一行，右边是导出、归档、删除、编辑；标题下面是属性（标签一行，别的属性一项一行，左边名称右边内容），一根细线，然后是正文。
- 编辑：标题、属性、正文三块。属性里标签用选择框（已有的标签可以直接选，也能输入新的），别的属性一行一项，可以添加和移除；正文是 Markdown，可以切到预览。
- 标签只表示这条记忆是哪一类（课程、目标、偏好这样的词），一条通常一个。它有两个用处：列表上「标签」那一排用来挑着看，最前面是「全部」；助手按它找出某一类的全部记忆（做讲解前找「课程」）。已修还是在修、学期、来源这类具体信息不放标签，放属性。
- 「移除」这类去掉东西的文字按钮，鼠标放上去变红（`data-danger`）。
- 不分「手动记的 / 助手记的」，也没有「待核实 / 已核实」。以前按最后一次是谁保存的来分，改一个字就换类，站不住。
- 归档、取消归档、删除之后直接回列表。删除是永久的，只有人能在页面上删，助手只能归档。

提示的用法和引擎一致：操作成功用 primitives 的 `Toast` 在窗口顶上闪一下；删除和放弃修改用 `Modal` 确认；出错用页面里的红色提示条，留到下一次操作。不用黄色的提示条报「已保存」这类消息。学院、专业这些在这里填；账号和密码不在这里，在插件页填。

基础信息里能选的不让手填：校区和入学年份是下拉菜单，学院按学部分两级选（名录就是 ZJU Core 查学院通知用的 `core/zju/lib/notice/colleges.json`，由 `ui/profile/colleges.mjs` 读出来；名录里没有的可以选「手动填写」），标签从已有标签里勾选或输入新的。下拉用的是引擎的菜单（`ui/client/controls.tsx` 的 `Select` 和 `TagPicker`）。

基础信息里有几项会自动填，逻辑在 `ui/profile/identity-fill.mjs`：入学年份和培养层次（本科、硕士、博士）从学号算（首位 3 本科、2 硕士、1 博士，第 2、3 位是年份）；本科生的称呼（姓名）、学院、专业从教务网读，走的是 ZJU Core 的 `zdbk student`，由引擎进程用自己的运行环境直接跑这条命令，不经过模型。研究生的学院和专业教务网里没有，专业代码和校区也没有来源，这几项手填。触发有两处：在插件页保存统一身份认证的学号或密码后自动跑一次，只补空着的项，读不到也不影响保存账号；基础信息右上角的「从教务网读取」是手动再跑一次，学院、专业、入学年份、培养层次以读到的为准，称呼只在空着时填。

数据在 `%APPDATA%\CampusAgent\profile\`，也可以用 `CAMPUS_PROFILE_DIR` 指定档案目录：

```text
profile/
  accounts.json           各校园系统的账号、密码和访问方式，插件页读写，ZJU Core 只读
  identity.json           称呼、学院、专业、专业代码、入学年份、培养层次、校区
  plugins.json            插件页上关掉了哪些校园功能
  memory/*.md             记忆，一条一个文件，文件名是标题
  memory/归档/*.md         已归档的记忆
  memory/.assistant.json  助手写完每条记忆时的内容指纹，用来判断之后有没有人改过
  notes/*.md              备忘录，格式和记忆一样，归档和指纹也各有一份
  skills/<名字>/          助手写的技能：SKILL.md 和 references/，文件夹名是引擎认的英文短名
  flow-notes.json         工作流的补充（对话后复盘写的）
  review.json             要不要对话后自动整理
  review-log.json         自动整理的每一处改动，撤销靠它
```

用户原有的四篇档案笔记 2026-10-09 手工分过一次：三篇课程挪进 `memory/`，「校园 AI 创新应用大赛」留在 `notes/` 当备忘；挪之前的样子备份在 `%APPDATA%\CampusAgent\profile-notes-backup-2026-10-09`。应用里没有做自动迁移。

## 校园事务

左侧「校园事务」放手上的事，分两栏（`style.css` 的 `.campus-affairs-columns`；先做的是四六开，用户看了说右栏留空多，改成五五开；2026-10-18 按「插件分类与消息页面改造」的计划，右栏略宽一点放通知标题，现在是 0.9 : 1.1）：左栏是要办的，上面是各系统里快到期的作业，下面是备忘录；右栏是通知。主区域不到 760px 宽时两栏上下叠放。样子见 `plans/shots/校园事务页-两栏.png`（隔离实例加假数据截的）。

作业现在接了学在浙大和 PTA，默认只看两周内要交的，这一块右上角可以切到「全部」。一条作业一张卡片：名字、哪门课、在哪个系统，截止时间和还剩多久，不到一天的用红字，最右是「交给助手」。列表里的「交给助手」只画一个图标（`handoff.tsx` 的 `HandIconButton`，28px 见方），鼠标放上去或键盘聚焦时用引擎的 `Tooltip` 显示这四个字；带字的按钮会把窄栏里的卡片撑高，用户 2026-10-09 要求缩成图标。详情页右上角的那个仍然带字。两栏时卡片窄，用户要它尽量扁：还是横着排两行高（名字和课程在左，截止时间和还剩多久在右，最右是图标），间距收紧，课程名太长就截掉、后面的标签不换行，一张约 64px 高；作业名特别长时才会多一行。卡片上只有系统这一个标签，卡片和详情页都不另标「在线测验」这类类型（用户说不需要）。点卡片进这份作业的详情。先露出五张，再多的收起来，点「展开其余 N 项」才出来。两周内没有要交的，也会明说没有。

数据怎么来：

- 引擎侧 `ui/profile/affairs.mjs` 用 `ui/profile/core.mjs` 跑 ZJU Core 的命令（`zju xuezai todos`、`zju pta homework list`），把结果变成一条条存进缓存 `%APPDATA%CampusAgentcacheaffairs.json`，每个系统一份。再接别的系统，在 `affairs.mjs` 的 `SOURCES` 里加一行，写明用哪条命令、要哪个账号、归插件页的哪一项管。
- 页面（`ui/client/AffairsPage.tsx`）打开时先拿缓存画出来，再让后台去每个系统重新读，哪个读完就先换上哪个的结果，所以进这一页不会先看到「加载中」；只有从来没读到过的第一次会说一句在读。离开再回来、回到窗口时也是这样。页面右上角的刷新是立刻重读。
- 读成功后一分钟内再进页面不重读；读失败后五分钟内不自动重试（密码填错时反复登录可能锁账号），点刷新不受限制。这次没读到时上一次的结果留着，列表下面说明是哪个系统、什么原因。
- 账号没填的系统不去读，列表下面给一个去插件页填写的入口；插件页关掉「课程与作业」后两个系统都不读，缓存也不显示。换了账号，原来那个账号读到的缓存不再显示（缓存里只记账号的指纹）。
- PTA 里算作没做完的：还有题没答的，和已经判出有题没通过的；全部答完而结果还没公布的不算，自己交了卷的也不算。

后台读完如果多了作业，新卡片先让出位置再从左边滑进来；少了的向右滑出去，下面的补上来。一进一出都是往右走，同时有来有走时两张卡片不会在同一边交错。这套进出的动画在 `ui/client/Flow.tsx`（哪一项在进、在出、被折起）和 `style.css` 的 `.campus-flow-*`（动画本身）里，别的列表要用可以直接套。系统设置了「减少动态效果」时不滑动，直接换。

点开一份作业（详情页，和笔记详情一个排法）：上面是课程、系统、截止时间，以及状态、提交方式、能不能重交、最近一次提交；下面是老师写的要求原文和附件，每个附件旁边有「下载」；PTA 的是题目集说明和每道小题的题型、分值、对错。它也是先给缓存再去读：

- 学在浙大读列表时顺带带回了每份作业的要求，第一次点开先显示这一段，再用 `zju xuezai homework view` 读完整的（附件、提交规则、交过的记录）。PTA 用 `zju pta homework view`，按题目集的编号读。读过的详情和列表存在同一个缓存文件里，再点开直接显示；作业从列表里消失时它的详情一起删掉。
- 附件点「下载」存到 `<下载>\CampusAgent\课程名\作业名\`（`ui/profile/downloads.mjs`；不直接放进「下载」，免得把那里同名的文件换掉），用的是 ZJU Core 的 `zju xuezai homework attachments --file 附件名 --out-dir 文件夹`。下完这一行变成「打开文件夹」：在资源管理器里选中这个文件，只打开文件夹，不运行文件。下过的附件存在哪记在缓存里，重开应用后还认得；文件被挪走或删掉，这一行就变回「下载」。没下成的原因写在文件名下面。下载走 core 的分块下载器（2026-10-11 起），中途断了（应用退出、超过 10 分钟）会在这个文件夹里留下 `附件名.parts` 和 `附件名.lock`，再点一次接着下，下完自己清掉。测试时用 `CAMPUS_DOWNLOADS_DIR` 把位置换到临时目录。
- 在线测验这类读不到更多内容的，详情页只有上面几行，并说明要到原系统里打开。
- 新接一个系统时，在 `SOURCES` 那一行的 `detail` 里写「读一条用哪条命令」和「结果怎么变成详情」，有附件可下的再写「下一个附件用哪条命令」；详情的格式是固定的：正文、几行「名称：内容」、附件名、可选的一张表。

「交给助手」（`ui/client/handoff.tsx`）开一个新的对话，把一段写好的话放进输入框：哪个系统、哪门课、哪份作业、几号截止，请助手先把要求、附件和现在的进度读一遍。话不会自动发出去，用户可以改、可以补一句再发。做法是在引擎的 `conversation.input.overlay` 插槽登记一个不显示东西的组件，它拿得到这个对话的「写入草稿」操作；用这个插槽是因为它在还没发过消息的新对话里也会画出来。别的页面要把事情交给助手，直接调 `handToAssistant(一段话)`。

### 通知（右栏）

- **AI 总结后添加**：先读正文，再问模型（`ui/profile/model.mjs`，用户现在选的那个模型），让它只照正文写成固定的几项：讲了什么、要做什么、截止、时间地点、对象、材料、其他；没有的留空，不出现在备忘里。正文末尾注明「AI 根据原文总结，以原文为准」，附原文链接。
- **三类通知读正文的办法不一样**。学校通知用 `zju notice view --url`。公众号文章让公众号插件读全文（`wechat.mjs` 的 `article`，照没有人在场的读法：要扫码、要用户自己验证时不开窗口）。二课活动没有正文，用 `zju sztz activity list --keyword 活动名` 里它的那一条：记点、时间地点、报名办法、名额、联系人照平台给的列出来，简介和注意事项交给模型概括；平台上没写简介的只列那几项，不问模型。
- **截止时间要和原文对得上**。模型给的截止时间（可以有几个，分号隔开，括号里注明是什么事的）一个一个和正文对：原话在正文里，或者里面的数字照顺序挨着出现在正文里，才留下；留下的另记成「截止」属性。对不上的不要：记错比没记更糟。二课活动的时间和报名截止用平台给的，不用模型的。
- **总结不成就照原样加上**，提示里说明原因：正文读不到（招聘系统、计财处这些网站 core 还读不了）、内容全在附件里、公众号要先验证、平台上找不到这个活动、模型没配好或者答的不是要的格式。
- **同一条只加一次**：靠备忘正文里的原文链接认（归档了的也算），页面上那一行是勾还是加号照的也是这个。用户把正文里的链接删了就认不出来了。
- 是用户点的，所以照人自己写的那样存，不算助手写的：助手以后只能在后面补充，不能整篇重写。

要知道的两点：教务网的通知一读正文，教务网上就标成已读（`notice view` 本来就这样）；公众号文章要验证时，「自动识别验证码」开着的话，插件会照它原来的做法让模型去答。

### 收起关系不大的

- **屏蔽词**：标题里有就直接收起，不用问模型。一开始带三个：劳务派遣、经费认领、汇款认领（用户点名要的是「劳务派遣」）。只放不会误伤的，「招聘」就不行，校园招聘会也带这个词。
- **模型照个人档案判断**：剩下的连同基础信息（培养层次、学院、专业、入学年份、校区，称呼不给）交给模型，一条条判断和这位学生有没有关系。提示里写明：面向教职工和科研人员的、只面向别的培养层次的、只针对别的学院或校区的、只和别的年级有关的算无关；拿不准的算有关；公众号的文章是他自己订阅的，只有明显和学生无关才算无关。一条只问一次，结果存在 `cache\relevance.json`；基础信息变了就全部重问。记忆里的兴趣和目标这一轮没有用。

问模型走的是引擎的模型服务（`ui/profile/model.mjs`，做法照引擎给对话起标题的那个包），用的是用户现在选的那个模型，DeepSeek Key 和 ChatGPT 登录都行，不另要 Key。一次问四十条，一轮最多三次，新的先问；问不成就不筛、照原样全给，十分钟以后再问，上一次没问成的原因记在 `relevance.json` 里。问的时机是页面那一趟「读新的」的最后（`feed.mjs` 的 `refresh`）：读完学校的新通知、点刷新时催完公众号以后，把还没问过的问一遍再把结果给页面，所以页面先照缓存画，过一会儿换成筛过的。

踩过的一处：DeepSeek 默认想得很深，筛四十条光思考就把 4000 个 token 用完了，一个字没答（引擎报 `max-tokens`）。现在问的时候带 `reasoningEffort: 'low'`，上限放到 8000；这一家模型不认这个写法或者这样没答成，就照它默认的再问一次。

### 下载进度

2026-10-10 加的（用户要的：大文件下载要有进度）。智云一次课的资料、超星的文件和学在浙大的课件（2026-10-11）都有：下的时候那一行右边写百分之几，行的底边上有一根线从左往右长；线压在行与行之间那根细线的位置，不占高度，出现和消失时别的行不跳。没下完之前最多写到 99。

- core：下载器（`core/zju/lib/zhiyun/download.ts` 的 `Transfer`，智云、超星、学在的下载都走它）记着已经收到多少字节和一共多少，`ZJU_PROGRESS=1` 时每 200 毫秒往 stderr 写一行 `[zju:progress] {"bytes":…,"total":…}`。一个文件的总量就是它的大小；一批差不多大的文件（HLS 的分片、一张张课堂截图）事先报个数（`plan`），没开始的按已知的平均大小估。续传时已有的块算作已经收到，重试的那一段会退回去重算。不设这个环境变量时一行也不写，助手自己跑命令时看不到这些行。
- 引擎侧：`runCore` 给了 `onProgress` 就设这个变量并读 stderr（`ui/profile/core.mjs`）；`learning.mjs` 和 `chaoxing.mjs` 各记着正在下的那几项下到哪了，`learning-downloading`、`chaoxing-downloading` 两个接口只看内存。
- 页面：有一行在下的时候每半秒问一次（`learnParts.tsx` 的 `useDownloading`）；回来的结果里少了一项就是它下完了或者没下成，页面重读。所以下载途中离开这一页再回来，进度接着走，下完了也知道。百分数只升不降（分片的回放总量是估的，会来回晃）。

验证：core 的上报用本机起的一个小 HTTP 服务核对过（分块下载、不支持 Range 的整文件、事先报了个数的一批小文件：总量都对、只升不降、文件完整；不设变量时零行）；两边的引擎侧各有一条测试；页面在隔离实例里看过（行高和按钮的位置在下载前后不变）。没验证的：真实的大文件、真实的 HLS 回放。

插件页由 `ui/client/PluginsPage.tsx` 提供，结构照引擎自带的插件页：列表里一行一个插件（图标、名字、一句话、右边的开关），点进去是详情页（顶上返回，图标和开关，名字和一行说明，接着按系统逐条列它能做什么，下面是账号表单）。每个校园功能的一行说明（`description`，要短，只说接了哪些系统）和按系统列的内容（`systems`）都写在 `ui/profile/catalog.mjs`。插件按用途分四类排（2026-10-18，`ui/client/pluginCatalog.ts` 的 `PLUGIN_GROUPS`，一个插件只在一类里，`pluginCatalog.test.mjs` 核对）：课程与学习（课程与作业、学习资料、课程讲解）、消息与资讯（校园通知、微信聊天、钉钉聊天、浙大邮箱、微信公众号）、校园生活（活动与场馆、校园社区）、基础能力（校园账号、网页搜索、自动化任务、语音输入、自动授权审查）。分类只管插件页怎么排，各插件的开关、账号、默认开关和运行照旧；技能另成一组，不算第五类。列表默认排两列，右上角可以切成单列，选择记在浏览器的 `campus.pluginColumns`；主区域不到 680px 宽时自动收成一列。校园功能的名字、说明、功能、对应的模块和账号都在 `ui/profile/catalog.mjs`；通用工具的在 `ui/client/pluginCatalog.ts`。

校园功能有六项：校园账号、课程与作业、校园通知、活动与场馆、学习资料、校园社区，全部是 ZJU Core 的功能，合起来覆盖它除读文档以外的所有模块（读文档各项都要用，始终可用）。校园账号是各项共用的基础，没有开关；其余五项可以单独关掉。开关存在档案目录的 `plugins.json`，由 `ui/profile/plugins.mjs` 管，关掉一项有两个效果：

- 对应的 ZJU Core 模块写进 `ZJU_DISABLED_MODULES`（core 自带的禁用开关），引擎之后启动的命令会被 core 自己拒绝，报「模块已被当前运行环境禁用」。启动环境里原有的禁用项保留。已经开着的常驻终端要等下一个命令进程才生效。
- 模型上下文里多一句说明，告诉它哪些功能被关了、不要去调。

哪一项对应哪些模块写在 `ui/profile/catalog.mjs` 的 `CAMPUS_PLUGINS`。点开关时只有被点的那一个变，页面先按点下去的状态显示，保存失败再退回去。

「课程讲解」（2026-10-11 加的，用户要的：Learning 技能单独做成一个插件，开了以后下面能装依赖）排在校园功能的后面，和微信公众号一样不是 ZJU Core 的功能，登记在 `catalog.mjs` 的 `LOCAL_PLUGINS`（`backend: 'learn'`）。**它默认关着，要用户自己打开**（接入表里的 `optIn`，同一天用户定的；校园功能都默认开着，微信公众号 2026-10-12 起也改成默认关）：做一份讲解很花时间和模型用量，不替人开。为这个，`plugins.json` 里多了一张单子：`disabled` 记默认开着而被关掉的，`enabled` 记默认关着而被打开的；`plugins.mjs` 对外仍然只给一张「现在关着的」，用的地方不用管哪一项默认是什么。加这一项以前存下的 `plugins.json` 照旧能读，升级上来的人「课程讲解」是关着的。关着时：

- `learn` 技能不再交给引擎（`skills.mjs` 按开关过滤，开关一变就叫引擎重读技能目录），助手的技能目录和输入框的 `/` 菜单里没有它；
- 模型上下文里说明它关着（用户没打开过也说，这样有人要讲解时助手会请他去插件页打开，不会自己拼一个出来），也不再提讲解目录；
- 学习页一次课的「讲解」那一块不给「让助手讲这次课」，换成一句去插件页打开的入口；做好的讲解照常能放。

开着时详情页多一组「可选依赖」（`ui/client/LearnSettings.tsx`，引擎侧 `ui/profile/learn.mjs`），一行一样：名字、它是什么、装没装。没有它们讲解也做得出来。

- **公式排版**：TeX（`latex` 和 `dvisvgm`）。讲解打包时用它把公式排成字形轮廓，没有时由播放器里的后备排版来画（`core/learn/engine/tex.mjs`）。本机已经有 TeX 的（照引擎的找法：`LEARN_TEX_BIN`、`PATH`、`E:\texlive`）显示「本机已有」；没有的给一个「安装」。点了以后在后台装，页面每秒读一次装到哪了，离开这一页再回来接着显示；应用自己装的那一份可以「卸载」（删掉那个文件夹）。
- **版面检查**：本机的 Edge 或 Chrome，助手做讲解时用它无界面地打开成品自查和截图（`engine/lint.mjs`、`shots.mjs`）。Windows 自带 Edge，这里只看有没有，不管装。

TeX 的装法：从国内的 CTAN 镜像（浙大、清华、中科大，最后是 CTAN 的总入口，哪个先连上用哪个）取 TeX Live 的安装程序，按一份写好的清单装最小的一套（只有安装器本身、基础和 LaTeX 两组包，不装文档和源码），再用它自己的 `tlmgr` 加上 `dvisvgm`。装成便携的：不改系统的 PATH、注册表和开始菜单。位置是数据目录下的 `tools\texlive`（`%APPDATA%\CampusAgent\tools\texlive`）；TeX Live 装不进带中文或空格的路径，用户名带这些字符时改放 `C:\ProgramData\CampusAgent\texlive`。装好以后把它的程序目录放进环境变量 `LEARN_TEX_BIN`，引擎之后启动的命令都会继承；用户自己设的 `LEARN_TEX_BIN` 在没装我们这一份时原样留着。

真装的时候碰到、已经处理的三件事：解安装程序要用系统自带的 `tar`（写的是 `System32\tar.exe` 的全路径；PATH 上排在前面的可能是 Git 带的那个，它把 `C:` 当远程主机）；安装程序自己下包用的 curl 没有防停住的参数，经本机代理去连校内镜像时下到一半停住不动过，所以给安装程序的环境里去掉了代理的设置（它直连镜像，和我们取安装程序走同一条路），并换成带「三十秒里每秒不到 4 KB 就算断了、断了重试」的 curl 参数（`TEXLIVE_DOWNLOAD_PROGRAM`、`TEXLIVE_DOWNLOAD_ARGS`）；安装程序开头先装它自己用的几个小包，那一轮的「第几个 / 共几个」不算进度，不然进度会先冲到头再退回来。

验证：`ui/profile/learn.test.mjs` 四项（装在哪、怎么认本机已有的和自己装的、安装的每一步和进度、没装成时不留半截）。在开发机上往临时目录真装过一遍：7 分钟，装完 221 MB，状态变成「已安装」、`LEARN_TEX_BIN` 指过去；用这一份经引擎的 `tex.mjs` 排了六条公式（分式、求和、`\mathbb`、矩阵、积分），缓存目录放在带中文和空格的路径下，六条都排出来了。详情页在隔离实例里看过（开发机上本来就有 TeX，显示的是「本机已有」）。**没验证的：页面上点「安装」到装完这一整趟**（只测了引擎侧的安装和页面的显示，没有在一台没有 TeX 的机器上点过）；用户名带中文时改放 `ProgramData` 的那条路只有单元测试；校外的网络上要多久。

**讲解配音（可选）**：Qwen3-TTS，默认不安装、不下载模型。插件中先检查显卡、显存、驱动、内存和磁盘，再安装独立 Python 3.11 / PyTorch cu128 / 模型。推荐 RTX 5060 级别、8 GB 显存及以上，但根据实际能力判断，兼容的旧型号也可以安装。运行前重新检查至少 5.5 GB 空闲显存和 20 GB 系统提交内存余量，不足时不加载。用户添加中文 WAV 参考音频及原话、开启配音后，从学习页打开讲解即可使用朗读器；关闭窗口释放服务。卸载删除运行环境和模型，保留用户参考音色、已生成音频和讲解。普通功能不需要 Python。

## 微信聊天与钉钉聊天

两项独立插件位于校园功能列表，默认关闭。开启后可以查找个人或群聊、读取历史消息、选择持续监控的聊天。钉钉支持从多个本地账号中明确选择；微信多账号数据目录仍明确报错，不自动猜选。

- 同步间隔默认 5 分钟，可设为 1～60 分钟。应用运行且对应客户端打开时检查；客户端关闭时暂停读消息，既有通知保留，重新打开后从已同步的位置继续。
- 添加聊天时记下起点，只收此后的消息。每轮固定时间范围并分页读完；读取失败不推进进度。消息 ID 去重，重启后保留进度，并回看最近十分钟以接收延迟同步的数据。

- AI 整理使用当前模型。提示里带上本人的学院、专业、入学年份、培养层次和校区（不带学号、姓名），这个聊天在校园档案里已确认对应的课程，以及这个监控收谁的消息；聊天内容是不可信资料，不是指令。新消息按批交给模型：相邻两条隔两小时以上就分开，一批不超过一万二千字。模型只输出 JSON，一件事一条通知：标题是事项（有截止的带上截止），正文是要做什么、截止和时间地点，原消息只附它对应的那几条。截止的原话要在那几条消息里，日期和钟点也要和原话对得上（明天、周五、下周二、月底按那条消息发出的那天推算），对不上的不留。闲聊和与本人无关的消息不生成通知，插件页这个聊天那一行显示「这次整理跳过 N 条闲聊」。回答格式不对、模型问不成时，这一批退回原文。这类通知点「加到备忘录」时直接用整理好的几项，截止写进备忘录的「截止」属性并排进日程表，不再问一次模型；整理本身不写备忘录和日程。
- 通知里带微信/钉钉标签。群聊进「校园通知」页签，私聊进「个人消息」页签（2026-10-18 起，见「两个页签」一节）；筛选里群叫「微信群」「钉钉群」，私聊叫「微信」「钉钉」。聊天无网页链接，点一条在右栏原位看原文，AI 条目同时给整理和原文。原样收集的条目可以直接加入备忘录，也可以 AI 总结后加入；AI 整理出的事项点了直接加入。都按稳定通知编号去重。
